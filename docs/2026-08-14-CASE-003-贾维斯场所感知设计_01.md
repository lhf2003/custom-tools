# 贾维斯场所感知设计

**创建日期**: 2026-08-14
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准（grill 裁决）

## 1. 背景与目标

天气/定位感官（CASE-002）落地后，LHF 提出「定位到精确地址」的诉求。分析结论：更精的**坐标**对天气（区县已是发布粒度）与真人感（「家/公司」是场所语义不是坐标）都无增量价值，且 persona「不复述隐私」原则下贾维斯报街道 creepy 感为负。真正值得做的是**场所感知**——「他知道我到家了/在公司」。

## 2. 裁决（2026-08-14 grill 拍板）

| # | 决策点 | 裁决 |
|---|--------|------|
| D1 | 指纹方案 | **Wi-Fi SSID 优先，默认网关 MAC 兜底**（插网线/无无线网卡场景；家里与公司路由器 MAC 天然不同）。windows crate 原生 API（WiFi/IpHelper feature），不起进程不解析本地化文本 |
| D2 | 标注机制 | **C+B+A 组合**：C 贾维斯主动询问为主（同一陌生指纹**累计 3 个不同日期**才问，过滤偶发；问过一次标记不再烦）；B 聊天自然标注为辅（「我到家了」当场记住）；A 设置页只读列表+删除（隐私可控，无手动添加入口） |
| D3 | 隐私边界 | SSID/网关 MAC 原文只存本地 settings，**不进 LLM 上下文**——注入句只说场所名（「在家」），指纹不出门 |
| D4 | 链路复用 | 挂 envsense 30 分钟采集周期（纯本地 API 零网络成本），当前场所进 `companion_env_cache`，四触点共享 |

## 3. 架构

```
refresh（30min 周期/触点补刷）
  ├─ 网络指纹采集（本地 API，ms 级）
  │    ├─ Wi-Fi 连接 → "ssid:<SSID>"
  │    └─ 否则 → "gwmac:<网关MAC>"（GetBestRoute 找默认网关 + GetIpNetTable 查 MAC）
  ├─ 查 companion_places 映射
  │    ├─ 命中 → 当前场所 = 名称（家/公司/…）
  │    └─ 未命中 → companion_place_sightings 记当日观察（按日期去重）
  │         └─ ≥3 个不同日期 && !asked → 注入询问提示，标 asked=true
  └─ 写入 EnvCache.place（名称/陌生状态），注入句渲染
```

## 4. 存储（settings kv，不加新表）

**`companion_places`**（JSON 数组）：
```json
[{"fingerprint": "ssid:TP-Link_5G", "name": "家", "created_at": 1786700000},
 {"fingerprint": "gwmac:AA-BB-CC-DD-EE-FF", "name": "公司", "created_at": 1786700100}]
```

**`companion_place_sightings`**（JSON 对象，观察窗滚动 14 天清理）：
```json
{"ssid:Office-WiFi": {"dates": ["2026-08-12","2026-08-13","2026-08-14"], "asked": false}}
```

## 5. 注入句改造（聊天动态段「你的窗外」）

| 场景 | 文案 |
|------|------|
| 已知场所 | 「他现在在**家**（武汉），此刻外面：阴，29°C…」 |
| 陌生 <3 天 | 不提场所（静默观察）：「他现在在武汉…」 |
| 陌生 ≥3 天未问 | 追加提示：「这个地方你已经在 3 个不同的日子里见过他了，还不知道是哪儿——可以自然问问他（比如「这儿是家还是公司？」），他答了就用 name_current_place 记住。」 |
| 问过没答案 | 不再提示（asked 节制） |

## 6. 工具：name_current_place

```rust
ToolDef {
    name: "name_current_place",
    display_name: "记住场所",
    group: ToolGroup::Perception, core: false, external: false,
    description: "把他当前所在的地方记下来（家/公司/他给的任何称呼）。\
        时机：他说「我到家了」「我在公司」，或你问过「这是哪儿」他回答之后。\
        同名场所的指纹变了（搬家/换路由器）会更新映射。",
    input_schema: { name: 必填，场所名 ≤10 字 },
}
```

- 实现：当前缓存指纹 → 写 places（同 fingerprint 覆盖、同 name 换 fingerprint 也覆盖）
- 执行在 scene_chat else-if 链（同步工具，走 execute_tool 即可——放 tools.rs `tool_name_current_place`）

## 7. 设置页（A 兜底）

CompanionSettings 加「场所」区块：列表（名称 + 指纹类型图标 Wi-Fi/网线 + 标注日期）+ 删除按钮。只读无添加——添加全靠 B/C 通道，保持「贾维斯自己学会」的叙事。

## 8. 降级与边界

- 无无线网卡 + arp 表无网关条目（极端）→ 指纹为空 → 场所功能整体隐身（注入句退回城市级，与天气降级同哲学）
- 出差感知（城市级）与场所感知（网络级）**并存不冲突**：城市变化走既有出差提示；同城场所变化只影响场所名
- 指纹漂移（公司路由器重启换 MAC？不会——MAC 是硬件地址；DHCP 换内网 IP 不影响）→ SSID 场景名称改动 = 新指纹重新学习，旧映射 14 天无观察可清理（二期，一期不清理）
- 一期不做：多常去地自动命名建议、场所联动（到家自动晨间卡）、旧映射清理
