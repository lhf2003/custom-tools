# MCP 与 SKILL 体系升级设计

**创建日期**: 2026-08-13
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准（grill 10 项裁决完毕，待实施）

## 背景

陪伴体系的手册（`skills/*.md` 自造 frontmatter）与工具（`tools.rs` 13 个声明）是三期
Skill 化的产物，但存在四个结构性问题：

1. **聊天目录收录过宽**：能力目录拼装由 `compose_chat_system` 共享（场景通道已注入，
   链路是通的），但收录过滤只有 `enabled`——diary/recall 等管道产物也进聊天目录，
   `trigger_description` 沦为可选提示而非准入条件
2. **对外 MCP 注册腐烂**：`~/.claude.json` 的 companion 注册指向 debug exe + 不存在的
   `custom-tools.db`（真库 `flowhub.db`），外部会话调 `get_memory_facts` 拿到空库
3. **工具暴露一刀切**：13 个工具全量对外，贾维斯内在状态工具（心情/经验本/手册治理）
   外部客户端可插手，治理闭环形同虚设
4. **能力不可见**：agent 具有哪些能力无页面展示，拓展无入口

## 裁决（grill 10 项）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 核心目标 | 规范化 MCP 工具 + SKILL：好拓展、页面可见；MCP 对外打通（外部客户端 → 贾维斯数据） |
| 2 | MCP 形态 | 单 exe 子命令 `--mcp-server`；注册指向真实安装路径 + app 自检自愈 |
| 3 | 工具分层 | 对内 13 / 对外 8（数据面），`ToolDef` 加 `external` 标记，`mcp.rs` 的 `tools/list` 按标记过滤；对外工具描述去人格化 |
| 4 | app 内 CC 通道 | **删除**：聊天（`chat.rs` agent 驱动）、日报（`agent.rs`）、analyzer/recall 的 CC 单次，全走场景模型；`jarvis_agent_available` 探测、`validate_claude_cli`、设置页 Claude Code 配置项一并撕掉 |
| 5 | SKILL 规范 | frontmatter 加 `tools` 字段（手册依赖的工具清单）；reporter/analyst 补 `trigger_description` 进聊天目录；diary/recall 永不进（管道产物） |
| 6 | SKILL 定位 | 不对外，只服务 app 内聊天；**目录收录收紧**为 `enabled && trigger_description 非空`——diary/recall 退出聊天目录，reporter/analyst 补触发描述后正式进 |
| 7 | 页面 | AI 区域新增 MCP、SKILL 两 tab；与既有「工具」tab 三足分工：工具=细粒度开关（现状不动，对外 8 工具加 badge）、MCP=对外连接与集成、SKILL=手册 |
| 8 | 内置保护 | 内置 5 手册 + companion server 不可删、不可开关（条目级）；工具粒度现有开关不受影响 |
| 9 | 本期边界 | SKILL 导入全通；MCP 第三方导入二期（client 层另行设计） |
| 10 | 外部 MCP 通道 | 保留（删的仅是 app 内 CC 引擎通道，方向相反） |

## 对外工具面（8 / 13）

对外（`external: true`）：`get_activity_summary`、`search_clipboard`、`get_habit_patterns`、
`list_memos`、`get_memory_facts`、`remember_fact`、`forget_fact`、`write_note`。

仅对内：`record_mood`、`append_evolution`、`propose_manual_edit`、`load_manual`、
`create_suggestion`（外部客户端插手心情/经验本/手册治理会破坏快照-备份闭环）。

## SKILL 导入通路（本期）

1. **入口**：SKILL tab「导入」→ 对话框：粘贴 SKILL.md 全文（主）/ 选择 .md 文件（次），不做 URL 拉取
2. **确认步（强制）**：解析出 name/description；`trigger_description` 必填（缺失则手册进不了
   聊天目录等于白导入），用户手填或「让 AI 起草」（场景模型读正文生成一句可改）；
   name 与内置/已有拓展重名 → 提示改名；附安全提示「外部手册会进入贾维斯的系统提示」
3. **存储隔离**：`app_data/companion/skills/custom/<name>.md` 子目录——`seed_skills` 不碰、
   删除保护由路径区分（后端删除命令校验必须在 custom/ 内）、`scan_skills` 递归扫描按路径标记来源；
   写入 frontmatter 固定 `enabled: true`、无 schedule（调度任务型不开放导入）

## MCP tab（本期）

内置 companion server 卡片：协议版本、对外 8 工具摘要、运行状态 + **注册自愈入口**
（检测 `~/.claude.json` 的 companion 注册：exe 路径/db 路径/notes 路径漂移 → 提示一键修复，
写入前备份 `.bak`；参数取当前 app 运行时的真实路径）。
