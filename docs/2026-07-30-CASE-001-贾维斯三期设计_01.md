**创建日期**: 2026-07-30
**作者**: LHF & Claude
**版本**: v1.0

## 背景

路线图 `docs/2026-07-28-CASE-001-贾维斯系统升级全盘路线图_01.md` 三期，目标：**工作手册从「调度器硬编码的脚本」升级为「可扩展的能力目录」，并给自进化装上刹车**。

四期交付后的现状：

- 4 本手册（reporter/analyst/recall/diary）`include_str!` 内嵌 + `load_role` 字符串 match 硬编码，加手册必须改 Rust 重编译
- 聊天两个通道都只有 `mcp__companion__*` 工具且工作目录隔离，贾维斯在聊天里读不到任何手册
- evolution.md 只能追加（`append_evolution`），无版本概念，16KB 死顶无提醒
- 建议的接受/忽略数据在 `suggestions` 表躺着，从不回写经验本

## 模块一：Skill 化手册基础设施

**目录结构**（运行时 app_data/companion/）：

```
companion/
├── persona.md              # 身份证（不动）
├── evolution.md            # 经验本
├── attitude.md             # 态度指引
├── skills/                 # 能力目录（新）
│   ├── reporter.md         # 日报手册（含 frontmatter）
│   ├── analyst.md
│   ├── recall.md
│   ├── diary.md
│   └── error-analysis.md   # 新：错误分析（首个聊天可激活手册）
└── backups/                # 版本快照（新，模块四）
    ├── evolution/20260730_143022.md
    └── skills/error-analysis/20260730_150111.md
```

**frontmatter schema**（极简单行标量，手写解析器，不引 yaml 依赖）：

```markdown
---
name: reporter
description: 每天晚上为他生成当日陪伴日报
schedule: daily 21:00
enabled: true
---
（正文：手册给模型的执行指令）
```

字段约束：`name` 必填且与文件名一致；`description`/`trigger_description` 进聊天能力目录；`schedule` 可选（机器可读，仅 daily/weekly 两种，本期仅 reporter 使用）；`enabled` 缺省 true。未知 key 忽略，解析失败的手册跳过并 log warn（不拖垮注册表）。**有 trigger_description 的才进聊天能力目录**——reporter/analyst/recall/diary 四本是调度器内部工作手册，不进目录。

**注册表**（新文件 companion/skills.rs）：

- `scan_skills(companion_dir) -> Vec<SkillMeta>`：读 skills/*.md，解析 frontmatter + 正文分离
- 聊天每次组装系统提示时现扫（几个小文件，代价可忽略，用户改文件立即生效）；调度循环每轮现扫（enabled/schedule 改动立即生效，无需重启）
- `load_skill_body(companion_dir, name) -> Option<String>`：按 name 读正文（剥 frontmatter）

**迁移**（启动时 seed_all 扩展）：

1. repo 内嵌 5 本默认版（原 agents/*.md 四本加 frontmatter 头 + 新一本），include_str! 路径不变
2. 运行时 skills/<name>.md 不存在时：若旧 agents/<old>.md 存在 → 读其内容前置 frontmatter 写入（**保留用户编辑**）；否则播种内嵌默认版
3. 旧 agents/ 目录一次性迁移后整目录删除（当日修订：不留兼容路径）；`load_role` 调用点（agent.rs/analyzer.rs/recall.rs/diary.rs）全部改走 `load_skill_body`，旧函数删除

## 模块二：聊天激活（能力目录 + 工具）

**能力目录注入**：compose_chat_system 在 `with_tools=true` 时追加（纯降级通道无工具，不注入）：

```
# 你的能力手册
以下手册可按需激活：他说的话匹配描述时，调用 load_manual 读手册全文，然后按手册执行。
- error-analysis: 分析错误堆栈定位根因。他粘贴报错/异常堆栈时激活。
```

**tools.rs 新增 2 个工具**（MCP 与 function calling 两通道自动获得）：

| 工具 | 签名 | 说明 |
|------|------|------|
| `load_manual` | `(name: string)` | 读 skills/<name>.md 正文；name 不存在返回可用手册列表提示 |
| `propose_manual_edit` | `(name, new_content, reason)` | 创建 manual_edit 建议（全文替换提案），不直接写文件——门控见模块四 |

**错误分析手册执行流**（验收场景）：他粘贴一段堆栈 → 目录命中 → load_manual("error-analysis") → 按手册结构输出分析（现象/根因假设/定位建议/修复方向/预防措施）→ 可顺带 create_suggestion 留存结论。全程 1 轮工具调用。

## 模块三：触发引擎

**不新建调度器**——长在现有 `run_scheduler` 60s 循环里，每轮现扫注册表：

```
check_manual_triggers(now, skills):
  for skill in skills where enabled && schedule 存在:
    到点判定：now >= 当日触发时刻（daily: 每天 HH:MM；weekly: 指定周几 HH:MM）
    今日未点火：settings 表 trigger_last_fired_<name> != today
    → 点火：写 trigger_last_fired，按手册类型执行动作
```

**动作语义（D4 当日修订）**：引擎只有一种动作——**自动执行**，本期唯一消费者是日报：

- **reporter（日报）**：既有自动流程的**调度移交**。`now.hour() >= DAILY_ANALYSIS_HOUR` 改为读 reporter.md 的 schedule；`companion_last_report_date` 成功标记、REPORT_RETRY_SECS 节流重试、`f.daily_report` 开关、启动缺报补跑全部照旧
- 引擎的价值不在「现在有几个消费者」，而在**调度权移交文件**：改触发时间从「改 Rust 重编译」变成「改 frontmatter 一行」（进化治理视图的编辑器里就能改，保存即快照）

**点火状态持久化**：settings 表 `trigger_last_fired_<name>` = YYYY-MM-DD（日报的成功标记 key 维持现语义，点火标记只防「同一 tick 日重复进入执行器」）。

## 模块四：进化治理

**快照**（companion/backup.rs 或并入 skills.rs）：

- `backup_file(companion_dir, rel_path)`：写入前复制到 backups/<rel路径>/<yyyymmdd_HHMMSS>.md，滚动保留 20 份（删最旧）
- 挂载点：append_evolution（工具层）、save_attitude、save_manual、apply_manual_edit（门控应用）、compact_evolution、rollback（恢复前再快照当前版）

**门控流**（D10）：贾维斯聊天中发现手册缺陷 → propose_manual_edit（全文新内容 + 理由）→ 建议中心出现待确认卡（类型 manual_edit，标题「贾维斯提议修改『错误分析』手册」，body=理由+变更规模）→ 接受：快照当前版→写入→当轮生效；忽略：作废。

**进化治理二级视图**（CompanionSettings 第三张入口卡，新文件 EvolutionGovernance.tsx）：

1. **手册列表**：注册表元数据（name/description/schedule/enabled）+ 点击展开内嵌编辑器（textarea）+ 保存（invoke save_manual → 快照+写入）
2. **经验本容量条**：当前字节 / 16KB 进度条 +「一键整理」按钮（compact_evolution：场景模型提炼冗余条目，快照兜底，登记 source=evolution_compact）
3. **备份列表**：按文件分组、时间戳倒序 +「回滚到此版」按钮

**16KB 提醒**：append_evolution 写入后检查文件 >14KB → create_suggestion（类型 evolution_cleanup，去重：有 pending 同类型不重复推）→ 引导去进化治理视图整理。

**新命令**：list_manuals / get_manual(name) / save_manual(name, content) / list_backups / rollback_backup(file, timestamp) / get_evolution_size / compact_evolution。manual_edit 的应用走 act_on payload 分支，不是新命令。

## 模块五：建议反馈闭环

**统计**（db.rs 新增 weekly_suggestion_stats）：按 suggestion_type 分组统计最近 7 天四态——accepted / dismissed / ignored（pending 且 created_at > 48h 前）/ seen（纯提示型，不计入比率只报数）。

**每周任务**（run_scheduler 夜间 21 点块内）：今天周日 && settings weekly_review_last_week != 本周 →

1. 统计全量数字（含 accepted 成功案例——防反馈循环偏差，路线图明示）
2. 场景模型自评 prompt：「这是本周弹窗处置数据…单类型样本 <5 只报数不下结论；有值得沉淀的写 1-2 条经验（做什么、为什么），没有就返回空」
3. 非空 → append_evolution「弹窗分寸」节（不门控，与 D10 一致；快照兜底）
4. 登记观测 source=weekly_review，成本面板可见；样本为零跳过不写不登记

## 新手册内容要点

**error-analysis.md**（正文指令）：他粘贴堆栈时激活；分析结构「现象一句话/根因假设（按可能性排序）/定位建议/修复方向/预防措施」；引用他给的堆栈关键帧，不编造他没给的上下文；信息不足就问；分析值得留存时经他同意后 create_suggestion 或由他决定记入经验本。

## 边界声明（本期不做）

- 机器可读触发只有 daily/weekly 两种 schedule：无 cron、无事件总线、无机器评估 exclude
- **周报功能取消**（当日修订）——原定首个自动执行新手册，取消后引擎消费者仅日报调度移交；read_note 工具一并取消（无消费者，聊天读日报碰壁再加）
- **推建议型触发动作（run_manual 链路）本期不建**——无任何手册使用
- 深度分析手册推迟；proactivity 字段不加（主动性分寸写进 trigger_description）
- 习惯模式系统不动（learning→confirmed→auto_executed 与引擎并存：模式管「他的习惯」，引擎管「手册的闹钟」）
- 外部编辑器修改不实时快照（上次程序化写入版本兜底；应用内编辑是主路径）
- 纯降级通道（无 tools）无手册能力——目录不注入，load_manual 不可用
- reporter/analyst/recall/diary 不进聊天能力目录（无 trigger_description，非用户按需激活）
- 手册级触发错过不补跑（日报/周报走各自的缺报补跑逻辑）

## 验收

1. 聊天里粘贴一段错误堆栈走完手册流程：目录命中 → load_manual("error-analysis") → 按手册结构输出分析（现象/根因假设/定位建议/修复方向/预防措施）
2. 进化治理视图改坏手册保存 → 备份列表出现旧版 → 一键回滚恢复，聊天下一轮即按回滚后内容执行
3. 改 reporter.md 的 schedule 到当前时间+2 分钟 → 到点日报流程自动触发（调度权移交文件生效，无需重编译）
4. 周日晚 21 点自评写回「弹窗分寸」节，成本面板可见 source=weekly_review 调用
5. 聊天中说「错误分析手册里加上 XXX 要求」引导贾维斯 propose_manual_edit → 建议中心待确认卡 → 接受后手册更新、旧版入备份
6. evolution.md 超 14KB 后收到整理建议，一键整理后容量回落、旧版可回滚
