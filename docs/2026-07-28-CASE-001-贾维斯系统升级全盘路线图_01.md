# 贾维斯系统升级全盘路线图（基于 Alice 方法论）

**创建日期**: 2026-07-28
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准（二期及以后为规划，逐期 grill 裁决后生效）

## 方法论来源与用法

本文档是 `docs/alice-methodology/`（Alice Agent 方法论，29 篇）在本项目（FlowHub 贾维斯陪伴系统）的落地路线图。读法：先看「方法论核心结论」，再看「现状盘点」，路线图每期标注对应的方法论章节与裁决状态。

**总纲（Alice 全书最重要的三个判断）**:

1. **Agent 产品的复杂度主要在状态管理，其次才是模型能力**——工程资源优先投 harness，不投模型选择
2. **System Prompt 是宪法不是便签纸**——KV Cache 命中决定成本结构；动态内容一律追加末尾
3. **成本工程是道德命题**——用户的 API Key 付费，每个设计决策要对得起用户钱包

## 一、方法论核心结论（16 条可迁移项）

### 设计哲学（ch.1)

| # | 结论 | 要点 |
|---|------|------|
| 1 | 接口长寿 | 工具声明格式、事件流类型定义只扩展不破坏；实现随时可换 |
| 2 | 状态优先 | 新功能先回答：状态住哪、谁读谁写、写了谁可见，答不清不写代码 |
| 3 | 结构隔离 | 工具（AI 可见）与服务（框架内部）严格分开；判断标准：「用户视角有意义的动作吗」 |
| 4 | 可丢弃组件 | 每个组件有降级路径；降级 = 质量下降，不是功能消失 |
| 5 | 可观测性 | 每个决策带 reason、每次 LLM 调用标记来源；事后补不上 |

### 上下文与记忆（ch.5、blog-04)

| # | 结论 | 要点 |
|---|------|------|
| 6 | 记忆分层分治 | 短期上下文 / 项目级文件 / 长期语义 / 用户认知模型，各按其生命周期选存储 |
| 7 | 写入在对话结束后 | 对话中立即写入会产生自我强化循环（AI 把自己刚说的话当历史再讲一遍） |
| 8 | 只提取用户消息 | 工具结果、子 Agent 输出、系统消息一律排除，防画像被稀释 |
| 9 | 情感记忆独立主体 | AI 记自己对用户的感受（日记），与用户记忆两套权限；日记私有 |
| 10 | 全量注入是死路 | 记忆增长后必须按维度/相关度召回；去重让 LLM 只看少量候选，成本恒定 |

### Agent 循环与工具（ch.3、ch.4、ch.15)

| # | 结论 | 要点 |
|---|------|------|
| 11 | 事件流是系统边界 | Agent 循环出口为事件流，UI/日志/子 Agent 都消费它；消费者控制节奏 |
| 12 | 工具是声明式契约 | 声明只读性、并发安全、权限需求；先读后写硬校验；大输出落盘返回路径 |
| 13 | 防呆优于依赖正确性 | 不假设模型每次都对（忘发送自动补发、孤立工具调用配对修复、压缩互斥守卫） |

### 提示词工程（ch.14)

| # | 结论 | 要点 |
|---|------|------|
| 14 | 分层注入 + 缓存友好 | 人格（极低频）→ 能力边界（低频）→ 上下文（中频）→ 动态追加（高频，末尾）;工具指南内嵌工具声明，按可用性动态注入 |

### Skill 与自进化（ch.9、ch.10)

| # | 结论 | 要点 |
|---|------|------|
| 15 | 四边界不混淆 | 工具=原子能力；Skill=流程知识；MCP=系统连接；System Prompt=全局指令。能用 Skill 解决的不做成工具 |
| 16 | 分层进化 + 硬门控 | 人格反思→配置热更→代码级，逐级加严；核心身份区代码级保护（哈希校验）;改进须用户确认 + 版本回滚 + 防退化（过度特化/语义漂移/指令膨胀/反馈偏差） |

### 活人感（ch.16、blog-02)

| # | 结论 | 要点 |
|---|------|------|
| 17 | 设定集是工程文档 | 叙事式 Prompt（「你是谁」非「你该怎么做」);「性格」措辞 ≫「许可」措辞（「你有内心独白的习惯」而非「你可以偶尔…」) |
| 18 | RPG 状态机 + 预规划 | 世界一致性来自状态机不来自随机；剧本前置（凌晨规划当日），用户不在场时 Agent 也「活着」 |
| 19 | 情绪/执行双通道隔离 | 情绪只写表达通道（语气/独白/日记），任务执行通道不读情绪；不数值化情绪；约束（经费/频率/隐私）构建真实感 |

### 模型路由与成本（ch.11、ch.0)

| # | 结论 | 要点 |
|---|------|------|
| 20 | 场景化模型配置 | 用户自选主模型 + 场景默认（记忆提取/分类用便宜模型）+ 超时降级；成本透明但不制造焦虑 |

### 多 Agent（ch.6、blog-05)

| # | 结论 | 要点 |
|---|------|------|
| 21 | 先判断任务类型 | 信息积累型 → 单 Agent + 好上下文管理；并发执行型 → 才上多 Agent。父子/Coordinator/Swarm 三模式按依赖结构选 |
| 22 | 隔离与人设 | 子 Agent 上下文/工具/记忆三重隔离，权限只降不升；每个角色独立人设（宁多套提示词不共用），输出不进用户记忆 |

### 安全与权限（ch.7、ch.12)

| # | 结论 | 要点 |
|---|------|------|
| 23 | 权限是光谱不是开关 | 模式→会话记忆→规则→AI 分类器（保守兜底）→用户确认的责任链；拒绝摘要注入上下文防反复碰壁；外部渠道独立白名单 |

## 二、现状盘点（2026-07-28)

### 贾维斯已有

- **人格体系**:persona.md（叙事式设定集，符合 #17)+ evolution.md 经验本 + 三本工作手册（reporter/analyst/recall，符合「手册=任务规则非人格」)
- **记忆系统（一期刚交付）**：逐会话提取（#7 #8 已落实）、五维分类、审计表、记忆中心、显式记忆工具、场景选维注入、memory_extraction 独立场景（#20 部分）
- **Agent 通道**:Claude Code CLI 驱动（agent 循环委托 CLI，事件流 jarvis:* 符合 #11)+ 场景模型回退（#4 部分：回退=能力减半，未达「质量下降而非消失」)
- **MCP 工具 ×9**:companion 数据工具，白名单受限（#12 部分：声明式但无并发/破坏标注）
- **后台服务**：窗口采集→21 点分析→日报→建议弹窗（服务/工具边界清晰，符合 #3)

## 三、路线图

### 一期：记忆系统升级 ✅ 已交付（2026-07-27)

- 设计：`docs/2026-07-27-CASE-001-贾维斯记忆系统升级设计_01.md`
- 裁决：7 项（提取时机/架构/分类/注入/情感记忆延期/记忆中心形态）
- 边界声明：相关度召回（facts>150 再议）、守门员、情感日记均不做

### 二期：活人感状态层 + 情感日记 + 观测性地基（下一期，方向已推荐，待 grill)

**目标**：贾维斯的行为从「静态人格」升级为「状态驱动的活人」，同时把成本黑盒打开。

| 模块 | 内容 | 方法论依据 |
|------|------|-----------|
| 轻量状态机 | 时间带 × 忙碌度（连续工作时长/AFK)× 关系阶段 → 注入聊天/弹窗/日报语气；状态从系统来不从随机来 | #18 |
| 情感日记 | 每晚一段私有日记（主体是贾维斯）→ 提炼「近期态度指引」注入聊天；情绪只写表达通道，执行通道不读 | #9 #19 |
| 今日关注点预规划 | 早晨基于 facts + 习惯模式 + 备忘意图生成当日关注清单，驱动弹窗时机与聊天开场（DayScript 桌面效率版） | #18 |
| 内心独白 | 聊天回复支持「小声」转场白语，与正式回答分离，可关闭；用「性格」措辞写 prompt | #17 #19 |
| LLM 调用观测 | 调用日志表（来源 chat/analysis/report/recall/diary、模型、token、耗时）+ 设置页成本面板 | #5 #20 |

**戒条（写进设计文档）**：不数值化情绪；弹窗频率上限（约束构建真实感）；日记私有不可查（适当不透明）。

**验收**：同一问题在上午/深夜得到语气不同但结果一致的回答；成本面板能回答「昨天日报/提取各烧了多少钱」。

### 三期：Skill 化手册 + 进化治理（已裁决，待实施）

- 设计：`docs/2026-07-30-CASE-001-贾维斯三期设计_01.md`
- 裁决：14 项（手册载体/聊天激活/触发引擎/触发动作/迁移范围/触发格式/家族扩充/周报产出/备份/门控/治理 UI/统计口径/自评形态/在线编辑）
- 边界声明：无 cron/事件总线、深度分析推迟、习惯模式不动、外部编辑不实时快照

**目标**：工作手册从「调度器硬编码的脚本」升级为「可扩展的能力目录」，并给自进化装上刹车。

| 模块 | 内容 | 方法论依据 |
|------|------|-----------|
| 手册元数据 | 触发条件（含反向排除）+ 主动性控制；聊天中贾维斯按需激活（如「帮我写周报」→ 周报手册） | #15 |
| 进化治理 | 手册/经验本版本备份与回滚；改进建议用户确认门控；evolution 16KB 将满时提醒整理（UI 入口） | #16 |
| 建议反馈闭环 | 弹窗接受/忽略率统计 → 每周自评 → 写回经验本「弹窗分寸」节（防反馈循环偏差：同时统计成功案例） | #16 |
| 手册家族扩充 | 周报、深度分析、错误分析（剪贴板堆栈已有雏形）等场景手册 | #15 |

**验收**：用户在聊天里说「帮我写周报」能走完手册流程；手册改坏能一键回滚。

### 四期：回退补齐 + 工程加固

**目标**：兑现「降级=质量下降而非功能消失」，补齐工程防呆。

| 模块 | 内容 | 方法论依据 |
|------|------|-----------|
| 回退路径工具能力 | 场景模型通道实现简易 tool-use 循环（OpenAI function calling 对接 companion 工具）,Claude Code 未开时贾维斯也能查数据/写笔记/记事实 | #4 #12 |
| 聊天上下文组装 | 回退路径历史消息分层压缩（保留首尾+摘要中段），替代目前的裸拼接 | ch.5 |
| 工程加固 | MCP 注册重试/降级；聊天单飞改排队（新消息不打断在飞回复）;CLI 路径保存时校验可执行；窗口标题入库脱敏 | #13 #23 |
| 建议中心 | 建议列表独立页（接受/忽略历史可查） | #5 |

**验收**：关掉 Claude Code 开关，贾维斯依然能回答「我昨天下午干了什么」并记住「记住我喜欢简洁回答」。

### 远期观望（默认不做，每期复盘时再评估）

| 方向 | 不做理由 | 触发再评估的条件 |
|------|---------|-----------------|
| 多 Agent 协作（ch.6) | 个人助理场景以信息积累型任务为主，Coordinator/Swarm 属过度设计；父子模式已由 claude CLI 内部承担 | 出现明确的并发型需求（如批量竞品调研） |
| 渠道桥接（ch.17) | 微信/TG 入口与桌面启动器定位冲突，安全边界成本高 | 有移动端/远程触达需求 |
| 朋友圈/社交（ch.18) | 游戏化过重，与效率工具 register 不符（以 PRODUCT.md 为准） | 产品定位转向陪伴优先 |
| 代码级自进化（ch.10 Widget) | 安全管线（扫描+沙箱+撤销栈）成本高，收益不明确 | 用户频繁要求自定义界面组件 |
| 向量语义记忆 | facts 规模小（<150)，分组全量够用 | facts 持续增长突破阈值 |

## 四、贯穿原则（每期设计与评审都要过一遍）

1. **状态优先**：新功能先回答状态住哪、谁读谁写、何时读写（#2)
2. **注入追加末尾**:System Prompt 前缀稳定，任何新增动态内容追加末尾（#14)
3. **工具/服务边界**:AI 主动触发且用户视角有意义 → 工具；否则 → 服务（#3)
4. **降级不消失**：新组件必须自带降级路径（#4)
5. **防呆**：不假设模型每次都对，关键动作有兜底检查（#13)
6. **成本对称**：新增 LLM 调用点必须同时登记来源标记，进成本面板（#5 #20)
7. **人格恒定区只走人工**:expectation/语气偏好进记忆层，不改 persona.md(#16)
