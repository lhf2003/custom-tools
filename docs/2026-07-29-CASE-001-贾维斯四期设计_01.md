| # | 问题 | 裁决 |

## 模块一：回退路径工具能力（tool-use 循环）

**核心动作**：把 9 个 companion 工具从 MCP stdio 层抽成协议无关的共用执行层，场景模型通道经 OpenAI function calling 调用同一套工具。

```
companion/tools.rs（新建）
  ├─ tool_definitions()  → 9 个工具声明（name/description/inputSchema，一份定义）
  └─ execute_tool(db_path, notes_dir, name, args) → Result<String, String>
       ↑ mcp.rs McpServer 改为薄协议适配（MCP 通道行为不变）
       ↑ scene_chat.rs tool-use 循环调用（新回退通道）
```

**降级链**（方法论 #4）：Claude Code agent → 场景模型+工具 →（模型/API 不支持 tools 时）场景模型纯问答。每级都是质量下降而非功能消失。不支持判定：首轮调用返回 4xx。

**新命令 `jarvis_chat_send_scene(session_id, text)`**：后端读会话历史 → 组装 → tool-use 循环（上限 4 轮）→ 最终结果经 `jarvis:chunk` 一次性推前端。事件契约与 agent 通道完全一致（start/status/chunk/done/error），前端两条通道统一为「发文本、听 jarvis:* 事件」。

**工具轮防线**：轮次上限 4；工具执行错误以文本回传给模型自我纠正；达上限后强制无 tools 收尾轮（基于已获信息直接回答）。

**llm 通道扩展**：`call_llm_with_tools` 支持 OpenAI/Ollama 双格式（Ollama 的 tool_calls arguments 是对象、OpenAI 是 JSON 字符串；tool 结果消息 OpenAI 用 tool_call_id 配对、Ollama 用 name），统一归一为 `ToolCall { id, name, arguments: Value }`。

**观测**：每一轮 LLM 调用独立登记 llm_call_logs（source=chat, channel=scene_model）——tool 循环烧几轮，面板看得见（原则 #5：新调用点带观测出生）。

## 模块二：聊天历史增量摘要压缩

裁决 D2 落地：rolling summary，替代裸拼接。

- `chat_sessions` 表加两列：`summary TEXT`（滚动摘要）、`summarized_up_to INTEGER`（已摘要到的消息 id 水位），幂等 ALTER 迁移
- 发送前检查：未摘要消息 > 24 条 → 最老的（总数-12）条调 LLM 压缩进 summary（旧摘要+新增对话 → 新摘要，200 字内），水位前移
- 组装 = system（末尾追加「# 此前聊天的摘要」段）+ 最近 12 条原文 + 本轮消息——动态内容一律追加末尾（#14）
- 摘要调用登记观测（source=chat_summary），成本面板可见
- 摘要失败不阻塞聊天：保留旧摘要、全量未摘要原文照带（质量下降非消失）

## 模块三：工程加固 4 小项

| 项 | 改动 | 效果 |
|----|------|------|
| MCP 注册重试 | `ensure_mcp_registered` 包 3 次重试（间隔 2s，CLI 冷启动/文件锁场景） | 注册偶发失败不再直接杀死日报 |
| 日报降级 | agent 失败就地回退场景模型版日报（`run_report_with_fallback`，调度与补跑两处统一） | CC 挂了的当天不再缺报，只是质量下降 |
| 聊天 FIFO 排队 | agent 通道 `JarvisChatChild` 加 queue、回退通道 `JarvisSceneChatState`（in_flight + queue）；两通道同一语义：在飞入队、答完自动续发；新增 `jarvis:start` 事件让前端复位流式状态；取消时清空队列 | 在飞回复不再被新消息掐死 |
| CLI 路径校验 | 新命令 `validate_claude_cli`（试跑 `--version`），保存时前端先调，失败琥珀色警告但不阻断 | 路径填错当场可见，不再是沉默失败 |
| 标题脱敏 | 采集源头 `sanitize_window_title`：标题关键词表（密码/银行/验证码/凭据/UAC 等）+ 密码管理器进程表（keepass/1password/bitwarden 等整窗脱敏）→ 替换为「(已脱敏)」 | 敏感标题从源头不进 DB，下游聚合/MCP/LLM 上下文都接触不到原文（#23） |

## 模块四：建议中心

CompanionSettings 二级视图（同记忆中心模式）：全部/待处理/已接受/已忽略四档筛选，每条卡片显类型徽章、时间、状态；待处理可补接受/忽略操作。数据源复用既有 `get_companion_suggestions` 命令，零后端改动。

## 设计偏移记录

| 偏移 | 说明 |
|------|------|
| 回退通道持久化职责 | assistant 落库仍由前端 jarvis:done 监听完成（与 agent 通道同一约定），后端只管处理与事件——前端事件监听零改动复用 |
| 排队触发摘要时机 | 摘要在发送前同步执行（每次发送最多一次短 prompt 调用），换来 token 上限可控；未选「发送后异步」（裸读全量有 token 风险） |
