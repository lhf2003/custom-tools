# 贾维斯二期设计：活人感状态层 + 情感日记 + 观测性地基

**创建日期**: 2026-07-28
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准（裁决 D1-D8 经 /ecc:plan 确认，当日开工）

## 背景与范围

路线图（`2026-07-28-CASE-001-贾维斯系统升级全盘路线图_01.md`）二期的落地设计。目标：贾维斯的行为从「静态人格」升级为「状态驱动的活人」，同时把成本黑盒打开。

五个模块：LLM 调用观测、轻量状态机、情感日记、今日关注点预规划、内心独白。

**戒条**（与路线图一致）：

- 不数值化情绪——情绪只写字，不打分不评级
- 弹窗文案与频率本期不动（现有冷却机制保持）
- 日记私有不可查——不做任何 UI 入口（适当不透明）
- 情绪只写表达通道（聊天注入），执行通道（分析/日报）不读

## 裁决表

| # | 决策点 | 裁决 | 备注 |
|---|--------|------|------|
| D1 | 成本金额来源 | CC 通道用 CLI 实报 `total_cost_usd`；场景模型 = token × 模型单价（`llm_models` 表可选两列，用户自填，未填只统计 token）。不做内置价目表 | 中转/代理价格各异，价目表维护是负资产 |
| D2 | 成本面板位置 | 「设置 → AI 模型」页尾「调用观测」区：今日/昨日/近7天 × 来源分组（次数/token/耗时/成本） | 翻译/QA 也登记，不属于陪伴，不放陪伴页 |
| D3 | 关系阶段判定 | 首次聊天日期起算三档：新识 <7 天 / 熟悉 <30 天 / 老搭档 ≥30 天；`settings.first_chat_date` 两个聊天入口自动记录 | 不引入 facts 数等复合指标 |
| D4 | 状态机形态 | 纯函数现场算（`state.rs`），不引入跨线程共享状态；输出叙事句只陈述事实，语气让模型自己演绎（#17 叙事式）；注入聊天 system prompt 与日报两通道末尾；弹窗不动 | 「状态从系统来不从随机来」(#18) |
| D5 | 日记通道与存储 | 新增 `Scene::Diary`（缺省跟随陪伴场景）；日记写 `companion/diary/YYYY-MM-DD.md`；蒸馏的「近期态度指引」写 `companion/attitude.md` 注入聊天；每晚分析后生成，失败不阻塞 | 日记无 UI 入口（戒条） |
| D6 | 今日关注点 | 基于 facts + 活跃意图 + 习惯模式 + 当日使用生成 3-5 条，存 `settings.daily_focus/daily_focus_date`；注入聊天 + 晨间卡升级为「关注+备忘」；跟随陪伴场景不新增 Scene | **生成时机有偏移，见「设计偏移」** |
| D7 | 内心独白 | 单次调用不加价：prompt 加「性格」措辞（「你有内心独白的习惯」），输出 `<aside>…</aside>` 标记；后端不动流协议，前端渲染层解析为灰小斜体心声；开关 `companion_monologue` 默认开 | 规避标记跨 chunk 问题；流式未闭合按到末尾处理 |
| D8 | 交付节奏 | 顺序三批独立提交：批A 观测（纯地基）→ 批B 状态机（无新 LLM 调用）→ 批C 日记+关注+独白（新调用点带着观测登记出生） | 原则 #6：新增调用点必须登记来源 |

## 批A：LLM 调用观测

### 表结构（`llm_call_logs`）

| 列 | 说明 |
|----|------|
| source | 调用来源：chat/analysis/report/recall/diary/focus/intent_parse/translate/qa/test |
| channel | `claude_code` \| `scene_model` |
| scene | 场景模型场景（chat/qa/translate/companion/memory_extraction/diary）；CC 通道为 NULL |
| model | 模型 id；CC 通道为 NULL（由用户 CLI 配置决定） |
| input_tokens / output_tokens | token 用量（流式通道记 0） |
| cost_usd | CC=CLI 实报；场景模型=token×单价（未配单价记 0） |
| duration_ms / status / error / created_at | 耗时、ok/error、错误摘要、epoch 秒 |

### 登记点（每个调用通道一处，失败也登记）

- `call_llm_with_scene`（陪伴统一路由）：CC 成功/失败各一条；回退场景模型由 `call_scene_model_llm` 登记（含单价估算）
- `agent::run_daily_report_agent`：日报 agent（usage + cost 从 result JSON 解析）
- `chat::stream_chat_process`：聊天流式 result 事件（原只 emit 前端，补落库）
- `commands/llm.rs`：`test_llm_connection`（source=test）与 `call_llm_stream_by_scene`（翻译/QA，流式无法取 token，只记次数/耗时——诚实的降级，面板标注）

### token 解析

- `llm::call_llm` 返回 `LlmReply { content, input_tokens, output_tokens }`：OpenAI 兼容读 `usage`，Ollama 读 `prompt_eval_count/eval_count`，缺字段容错为 0
- Claude CLI result JSON 读 `usage.input_tokens/output_tokens` 与 `total_cost_usd`

### 单价配置

`llm_models` 加 `input_price_per_m` / `output_price_per_m` 两列（美元/百万 token，REAL 可空，幂等 ALTER 迁移）；模型列表行内两个输入框（非受控 defaultValue + 失焦提交，空串=清除）。

## 批B：轻量状态机

`state.rs` 纯函数：`current_state_sentence(conn, now) -> String`，三因子：

1. **时间带**：清晨(5-8)/上午(9-11)/中午(12-13)/下午(14-17)/傍晚(18-21)/深夜(22-4)
2. **忙碌度**：当前未闭合活动段（`activity_log` 最新 `ended_at IS NULL`）的连续时长；无当前段省略该句
3. **关系阶段**：`settings.first_chat_date`（首次聊天时由 `jarvis_chat_send`/`jarvis_chat_system` 记录）至今三档；未记录省略该句

输出示例：「现在是深夜 23:40。他已经连续工作 3 小时 20 分钟。你们相处 42 天了，老搭档。」

注入点（均追加 prompt 末尾，前缀稳定段不动——原则 #2）：聊天 `compose_chat_system`、日报 agent prompt、场景模型版日报 prompt。单测 5 个（时间带/阶段/完整句/可缺省段/不足一分钟跳过）。

## 批C：情感日记 + 今日关注 + 内心独白

### 情感日记（`diary.rs` + `agents/diary.md`）

- 调度：每晚 21 点分析链末尾（模式挖掘 → 记忆提取兜底 → **日记 → 明日关注**），独立于日报开关，失败只记日志
- 素材：当日活动聚合 + 最近 10 条用户聊天消息 + 今日记忆变更 + 上次态度指引
- 输出契约（写进 diary.md 手册）：日记正文 → 单独一行 `===态度===` → ≤120 字态度指引；单次调用两段输出，省一次蒸馏调用
- 防呆：无分隔标记时整篇存日记、attitude 不动；attitude 截断 300 字（注入膨胀保护）
- 存储：`companion/diary/{date}.md` + `companion/attitude.md`（persona.rs 提供 load/save，不播种）

### 今日关注点

- 生成：前夜 21 点随分析链（见设计偏移），任务式精简 prompt（不带 persona 全文，成本意识），跟随陪伴场景，source=focus
- 存储：`settings.daily_focus` + `daily_focus_date`（明日日期）；读取侧仅当 date==今天生效（`diary::today_focus`）
- 消费：聊天注入「# 你今天的关注」段；晨间卡正文从纯备忘清单升级为「今日关注 + 备忘待办」

### 内心独白

- prompt 段（开关门控，性格措辞）：「你有内心独白的习惯：偶尔会把一闪而过的真实想法用 `<aside>…</aside>` 裹起来说——那是你的小声嘀咕，不是回答正文的一部分。不是每句话都值得嘀咕，有感觉才说，别硬凑。」
- 渲染：ChatView `splitAsides` 切分正文/独白段，正文走 ReactMarkdown，独白渲染为灰小斜体左边线块；未闭合 `<aside>` 按到末尾处理（流式不断裂）
- 开关：`companion_monologue`（AppSettings → CompanionFlags 运行时镜像 → 宏命令 → settingsStore → 陪伴设置页 Toggle，默认开）

### Scene::Diary 迁移

`llm_scene_configs` 的 CHECK 约束不含新值时整表重建（沿用 memory_extraction 同款迁移机制）；`default_scenes` 与前端 Scene 类型/标签同步。

## 设计偏移（对 D6 裁决的偏离，已告知 LHF）

关注点生成时机从「晨间首次活动时」改为「前夜 21 点随分析链」。理由：更贴合 Alice 预规划原义（#18 剧本前置——用户不在场时 Agent 也在「活」），且避免 collector 线程阻塞等 LLM；晨间卡零延迟直读。若 LHF 不认可可回退为晨间生成。

## 边界声明（本期不做）

- 弹窗文案与频率机制（现有冷却保持，三期建议反馈闭环再议）
- 日记 UI 入口（戒条：私有不可查）
- 流式通道 token 计量（OpenAI 流式 usage 需 `stream_options.include_usage` 协商，中转兼容性有风险）
- 内置模型价目表
- 情绪数值化、多维度情绪模型（戒条）

## 验收

1. 同一问题在上午/深夜得到语气不同但结果一致的回答（状态句注入生效）
2. 成本面板能回答「昨天日报/提取各烧了多少钱」（按来源分组，次数/token/成本可查）
3. 重启后 `companion/agents/` 四本手册齐全（diary.md 随 seed_all 播种）
4. 日记落盘 `companion/diary/YYYY-MM-DD.md`，attitude.md 注入聊天（问「你最近心情怎么样」可见风格变化）
5. 独白开关关闭后回答只剩正文
