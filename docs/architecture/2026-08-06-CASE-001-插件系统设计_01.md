# 插件系统设计（一期：内置视图插件协议）

**创建日期**: 2026-08-06
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准

## 1. 目标与定位

**一期目标是对内架构重构**：把现有 5 个视图模块抽象为统一的「插件协议」（manifest + 自动发现注册表 + 生命周期通道），消灭分散在壳里的手工同步点，使新增视图功能 = 加一个目录 + 一个 `plugin.ts`。

协议形状为将来的外部插件生态（Raycast/uTools 形态）预留扩展位，但**一期不实现外部插件**（无沙箱、无权限模型、无分发）。

### 现状痛点（重构动机）

一个视图模块当前要在 5 处手工登记才能完整工作，漏改即静默失效：

| 登记点 | 内容 | 文件 |
|---|---|---|
| 启动器入口 + 操作手册 | id/name/icon/aliases/description | `src/constants/tools.ts` |
| 视图渲染 | `renderView()` switch case | `src/App.tsx` |
| 导航栏配置 | title/menuItems/primaryAction/menuLabel | `src/App.tsx` viewConfigs |
| 快捷键映射 | 后端 moduleId → 前端 ViewMode | `src/App.tsx` MODULE_VIEW_MAP |
| 视图跳转白名单 | OPEN_VIEW_TARGETS 数组 | `src/App.tsx` |

另有壳对插件的知识泄漏：`appStore` 中的 `jsonFormatterData` / `pendingOpenNotePath` 字段、App.tsx 中的 clipboard 专属逻辑（清空/导出/右键菜单/条目动作分发）。

## 2. 边界划分

| 模块 | 归类 | 说明 |
|---|---|---|
| json_formatter / clipboard / markdown / password / everything | **视图插件** | 一期协议覆盖的全部插件 |
| launcher / settings / chat | **外壳** | chat 与 launcher 共享无导航栏 home 布局，且被系统事件直接驱动，归壳 |
| companion / search | **平台服务** | 无视图常驻服务/后端能力，不进插件协议 |

协议预留 `kind` 字段（当前唯一值 `'view'`），将来后台服务类能力可以 `kind: 'background'` 增量加入，不破坏已有 manifest。

## 3. 插件 Manifest（冻结）

每个插件目录下一个 `plugin.ts`，导出单一 manifest：

```ts
interface PluginTrigger {
  keyword: string;    // 如 '@json'，行首前缀匹配，大小写敏感
  argHint?: string;   // 占位提示，如 'JSON 文本'
}

interface ViewPlugin {
  kind: 'view';
  id: string;                                        // 如 'clipboard'
  name: string;                                      // 如 '剪贴板'
  icon: LucideIcon;
  aliases: string[];                                 // 启动器搜索别名
  description?: string;                              // 操作手册文案
  order?: number;                                    // 网格/手册排序，缺的排最后
  shortcutModuleId?: string;                         // 仅映射后端 moduleId（吸收 notes/passwords 旧 id 不一致），非声明机制
  triggers?: PluginTrigger[];                        // 启动器前缀路由
  load: () => Promise<{ default: ComponentType }>;   // 懒加载视图，得代码分割
  nav: {
    title: string;                                   // 导航栏标题
    menuLabel?: string;                              // 菜单按钮文案（如「操作」）
    useMenuItems?: () => MenuItem[];                 // hook 形式，支撑运行时禁用态/文案切换
    contextMenu?: boolean;                           // 内容区右键浮层（复用 useMenuItems 输出）
  };
}
```

设计要点：

- **menuItems 必须是 hook 而非静态数组**：剪贴板菜单依赖选中态（禁用/文案切换/图片专属项），壳在当前插件激活时于固定位置无条件调用该 hook，插件切换以 key 重挂载保证 hooks 规则。
- **插件只声明自己的菜单项**；公共项（窗口置顶 / 设置 / 关于）由壳渲染菜单时统一追加，「设置」项在 settings 视图自过滤。
- `load()` 懒加载使各插件视图自然代码分割，启动不再全量打包。

## 4. 注册表与类型

**自动发现**：`import.meta.glob('../modules/*/plugin.ts', { eager: true })`，目录中存在 `plugin.ts` 即成为插件，零登记。glob 是编译期静态展开，非运行时扫描，tree-shaking 与类型推导不受影响。manifest eager、视图本体 lazy。

**目录结构不动**：插件与壳模块继续混住 `src/modules/`，以 `plugin.ts` 存在与否区分身份。

**ViewMode 类型分层**：

```ts
export type ShellView = 'launcher' | 'chat' | 'settings';
export type ViewMode = ShellView | (string & {});
```

- 壳视图保字面量（renderView 对它们有真实分支逻辑：isHome 布局）
- 插件 id 开放为字符串，运行时校验收敛于注册表的 `isPluginView(id)`，未知 id `console.warn` + 回退 launcher（替代旧 OPEN_VIEW_TARGETS 的静默拒绝）
- 各模块 `setActiveView('clipboard')` 调用点零改动

## 5. 壳机制

### 5.1 打开载荷通道

```ts
// appStore
payloads: Record<string, unknown>;                       // pluginId → 待消费载荷
openPluginView: (id: string, payload?: unknown) => void; // 写载荷 + setActiveView
```

- 插件侧配消费 hook（读出自己的载荷并清除），载荷类型 `unknown`，插件自己 narrow
- 订阅式 store 同时覆盖两种时序：插件未挂载（挂载时消费）与已挂载（订阅直接触发，如 markdown 已打开时再收 notePath）
- `app:open-view` 事件的 handler 收编为调 `openPluginView(detail.view, detail.payload)`，OPEN_VIEW_TARGETS 白名单删除
- 删除 `appStore.jsonFormatterData` / `pendingOpenNotePath`；保留 `chatPrefill`（chat 是壳）

### 5.2 启动器集成

- 结果集 = 壳入口（`SHELL_ENTRIES`：settings/chat 两条常量）+ 注册表插件 + 外部应用，插件顺序按 `order`
- 壳入口是封闭集合，壳自己是自己唯一的登记处，不构成同步点
- chat 的 Tab 切换入口保留不动，网格入口为额外搜索路径

### 5.3 Trigger 前缀路由（uTools features.cmds 形态）

- 查询行首命中某插件 trigger 时，结果区**独占**该插件（短路普通搜索），回车调 `openPluginView(id, 剩余文本)`
- 裸 trigger（无参数）回车 = 打开插件不带载荷
- 行首匹配、大小写敏感（`@JSON` 不命中，避免与普通搜索词撞车）
- 现有「粘贴 JSON 自动跳 json_formatter」联动改走 `openPluginView` 载荷通道，与 `@json` 殊途同归
- 「记 xxx」备忘不打开任何视图，保持启动器特例，不进 trigger 体系
- 首个用例：`@json`；`@time` 日期转换工具将作为协议的第一个新插件验收用例（后续迭代）

### 5.4 渲染与错误兜底

- App.tsx 职责收敛为纯壳：渲染当前视图、调用当前插件 `nav.useMenuItems()`、渲染菜单/右键浮层、统一追加公共菜单项
- 导航栏（标题/菜单来自 manifest 同步数据）即时渲染，**不参与懒加载**
- 内容区 Suspense fallback 为居中 spinner；外层 ErrorBoundary 捕获 chunk 加载失败，显示「加载失败 + 返回启动器」，详细错误进 console
- **加载态消除（双保险）**：① 模块级 lazy 缓存（PluginHost 用 `lazyViewCache` Map 跨重挂载复用 lazy 实例）——已访问插件切回零挂起零闪烁；② 启动 1s 后 `preloadPlugins()` 预加载全部插件 chunk（本地并行、失败静默）——首次进入也即开即现。spinner 降级为纯兜底
- 右键浮层：壳读当前插件 `nav.contextMenu`，为 true 时在内容区接管右键（保留输入框 WebView 原生编辑菜单避让），用 `useMenuItems()` 输出渲染

## 6. 一期不做（显式排除）

| 排除项 | 去向 |
|---|---|
| Rust 后端改动（command 自注册等） | 不做，前后端 invoke 字符串接缝维持现状 |
| 插件启用/禁用 | 随外部插件（二期以后）一起来，届时是刚需 |
| 设置贡献点（插件声明配置 UI） | 二期；配置项继续集中壳设置页 |
| 快捷键声明贡献点 | 二期；全局快捷键清单保持 `shortcuts.rs` 硬编码（启动期 OS 注册，后端是真相源） |
| `kind: 'background'` 后台插件 | 预留字段，companion 类能力将来按需进入 |
| 外部插件（沙箱/权限/分发） | 远期，协议已预留扩展位 |

## 10. 决策记录（grilling 过程归档)

本设计经 15 轮逐项裁决，关键取舍：

1. 对内重构优先，协议为外部插件预留 —— 单人项目无第二作者，B 的权限/版本/分发是纯成本
2. chat 归壳 —— 与 launcher 共享 isHome 布局且被系统事件驱动，抽出收益小牵动大
3. menuItems 用 hook —— 剪贴板菜单的运行时状态依赖，无法纯数据化（Raycast 的 actions 同理是组件）
4. 目录不搬家 —— `src/plugins/` 搬迁是纯 churn 且损失 git 历史可追溯性
5. trigger 独占模式 —— `@` 前缀是强意图信号，普通搜索结果全是噪音
6. 公共菜单项壳统一追加 —— 避免 5 份重复与新增插件遗忘
7. 单批次迁移 —— 项目规则禁止兼容性代码，双轨即两份真相
