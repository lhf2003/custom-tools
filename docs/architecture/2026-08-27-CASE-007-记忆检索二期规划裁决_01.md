# 记忆检索二期规划裁决（grill 定案）

**创建日期**: 2026-08-27
**作者**: LHF + Claude
**版本**: v2.0（同日修订：维度 2560 / 历史不迁移 / WeMM 本地为终点）
**状态**: 已批准

> 本文档是记忆检索二期的 grill 裁决纪要，与一期设计文档 `2026-08-27-CASE-001-多模态记忆检索系统设计_01.md` 配套。复审勿翻案；与一期裁决冲突处以本文档为准。v2.0 修订：Q2/Q5/Q10 改写，新增 Q11，推翻 v1.0 的「API 先行进生产」路线。

## 背景

一期（M0-M4）已收官：浏览器扩展采集 + native messaging + sqlite-vec + 本地 bge-small-zh ONNX，纯文本检索全本地。

二期规划的触发点有二：一期裁决预留的「WeMM 增强包」方向，以及对开源项目 [Indexed](https://github.com/xiaotianfotos/indexed) 的调研——该项目验证了「整段 10s webm 视频直送多模态 embedding」路线（其作者从抽帧路线迁移而来），并提供了 qwen 系多模态 embedding 服务的调用格式参照。

技术事实（2026-08-27 查证，来源见文末）：

- **qwen3-vl-embedding**（阿里云百炼）：支持文本/图片/视频输入，视频单文件 ≤50MB，32K token 上下文；Matryoshka 截断可选 2560/2048/1536/1024/768/512/256 维；文本 ¥0.0007/1K tokens、图片视频 ¥0.0018/1K tokens，免费额度 1M tokens（90 天）。**二期 API 验证统一使用全维 2560，不做截断**。
- **腾讯 WeMM-Embedding**（Apache 2.0，2B Python 栈）：本地主力模型，一期裁决原定 512 维 Matryoshka 截断作为初值，最终维度在 N0 验证中定。
- WeMM 空间、qwen3-vl API 空间（2560 维）**互不兼容**；API 阶段向量在 WeMM 切换时作废。
- 一部 30 分钟视频（180 个 10s 分片）embedding 成本约 ¥0.2-2（API 口径）。

## 裁决事项

### Q1 范围：浏览器侧深化

二期 = 多模态增强包（图片模态解锁 + 浏览器视频**整段 embedding**，弃抽帧路线）+ API 入口选项（qwen3-vl-embedding）。**本地视频文件索引（ffmpeg 路线）留三期**。

- 弃抽帧的依据：Indexed 作者从抽帧迁移到整段视频 embedding（schema `visual-10s-v2` → `native-video-10s-v1`），实战投票；
- Indexed 的 canvas captureStream + MediaRecorder 方案与参数（10s/4fps/720p/1.6Mbps）作为起步配置；
- 本地视频文件是全新采集源（ffmpeg 管线 + 批量任务 UI），不与模型大变量混在同一期。

### Q2 推理栈：WeMM 本地为终点，API 仅验证工具（v2.0 改写）

**主力是本地模型（腾讯 WeMM-Embedding），qwen3-vl API 只用于 N0 链路验证，不进生产。** v1.0 的「API 先行进生产、sidecar 后置可选」作废。

- N0 用 API 快速验证检索质量与链路可行性（2560 全维）；N1 起正式空间直接建在本地 WeMM 上；
- 云端 API 降级为可选「云端模式」入口（见 Q11），Q7/Q8 的开关与 BYOK 设计随之迁移；
- 升级路径：一期 bge 继续服役至 WeMM 就位 → 存量全量重 embed → 卸载 bge/onnxruntime。

### Q3 视频画面触发：纯 opt-in

播放器内注入启停按钮（YouTube/B站），用户主动选择才做画面索引，未选择不碰。成本与算力完全由用户控制。字幕索引维持一期自动行为不变（embedding 模型随空间切换）。

### Q4 图片触发：分级

- **页面主图**：跟随正文采集**自动** embedding（公开网页内容，敏感度接近 URL；继承一期黑名单机制）；
- **剪贴板图片**：本地存储照一期不变，用户点「索引此图」才 embedding（截图含密码/私聊/代码，最高敏数据类型）。

### Q5 向量空间：统一空间（归属本地 WeMM）

单空间单路，不做双空间融合。v2.0 明确：**正式空间归属本地 WeMM**，API 的 2560 维空间仅存在于 N0 验证环境，其向量不迁移、不进生产。

- 依据：双空间分数不可比、融合排序是长期负担；统一空间下「本地/云端模式互斥切换 = 全量重 embed」即可维持单空间不变式（见 Q11）；
- 存量 bge 数据在 WeMM 就位后全量重 embed（`memory_items.content` 原文在库，可行）；**API 验证阶段不动历史数据，测试语料验证即可**（LHF 2026-08-27 明示）。

### Q6 bge：完全弃用

WeMM 就位并完成存量重 embed 后，卸载 bge 模型 + onnxruntime 依赖（安装包瘦约 100MB），不做离线兜底、不做 FTS5 降级。WeMM 本身即本地模型，「断网检索不可用」在终点架构中不成立（仅 N1 开发空窗期内一期 bge 继续服役）。

### Q7 云端模式开关：默认关 + 引导开启（迁移至云端模式入口）

云端模式**默认关**。开启流程：明示出域数据清单（页面正文、字幕、查询词、页面主图、opt-in 图片/视频）+ 引导配置黑名单，一键开启后激活 API。本地模式（默认）下数据不出本机，一期「默认不出本机」叙事在终点架构中完全保留。

### Q8 API key：BYOK

云端模式使用用户自带百炼 key，开启流程引导注册 + 粘贴 + 一键验证；**Windows DPAPI**（CurrentUser 范围）加密存储，后台检索免密读取。不内置 AK（embedding 是持续数据流，内置 = 为用户用量买单 + 配额/防滥用体系；天气内置 AK 先例不适用）。

### Q9 保留策略：全部永久（推翻一期 90 天滚删）

所有记忆数据永久保留，仅用户手动删除。

- 一期 purge 调度（启动 + 24h）退役，仅保留手动清空入口；
- 隐私文案改为「永久保留，随时可手动删除」；
- 后续需在记忆中心补按时间段/域名的批量管理工具（N1 schema 预留管理字段）。

### Q10 分期与验收线（v2.0 重排）

| 里程碑 | 内容 | 验收线 |
|---|---|---|
| **N0 spike 双轨验证** | 轨 1（API）：qwen3-vl **2560 全维**，一期同语料（488 条 + 16 查询）文本回归、10s webm 视频链路、API 延迟；轨 2（本地）：裸 Python 跑通 WeMM——加载、embed 文本/图/视频、CPU 推理速度、512 截断质量损失 | **文本 top-3 ≥ 88%（不低于 bge，硬红线）**；WeMM CPU 速度可接受（标准 spike 中定）；文搜视频人工评估达标。**WeMM 轨若卡住，退回「API 进生产」路线重新裁决** |
| **N1 WeMM 正式空间落地** | sidecar 工程（Python 嵌入式打包、模型分发、native 集成形态）、schema 加模态/保留类别/管理字段、WeMM vec 表、存量重 embed、卸载 bge/onnxruntime | E2E：全本地检索可用，bge 完全移除 |
| **N2 图片模态** | 页面主图提取自动 embed、剪贴板「索引此图」、启动器图片结果展示（全本地） | E2E：主图可检索、剪贴板 opt-in 生效 |
| **N3 视频画面** | YouTube/B站播放器 opt-in 按钮、10s 分片采集、webm duration 修复、WeMM 视频 embedding、画面结果缩略图 + `?t=` 跳转 | E2E：opt-in 视频画面可检索可跳转 |
| **N4 云端模式（可选）** | qwen3-vl API 作为用户可选模式：BYOK + DPAPI + 默认关 + 出域清单引导（Q7/Q8 设计在此落地） | 届时单独裁决细节 |

### Q11 模式互斥：本地/云端同一时刻单模式单空间

WeMM 空间与 qwen3-vl API 空间互不兼容，为避免双空间分裂：**本地模式与云端模式互斥，同一时刻只有一个生效；切换模式 = 该模式空间的全量重 embed**（文本原文在库可重跑；图片/视频原始素材不留底，切换后需重新采集/索引——切换流程须明示此代价）。

- API 验证阶段（N0）不产生生产数据，不受此约束；
- 原始素材不留底的决定依据：10s webm 约 2MB/段，一部 30 分钟视频约 360MB，全量留底存储成本不成立。

## 与一期裁决的冲突清单（本文档优先）

| 一期裁决 | 二期改定 |
|---|---|
| 浏览正文默认不出本机 | 终点架构全本地（WeMM），叙事恢复；仅云端模式（默认关）下出域（Q2/Q7） |
| 90 天滚动删除 | 全部永久，手动删除（Q9） |
| 二期 WeMM 增强包「用户主动下载的可选项」 | WeMM 升格为正式空间主力，非可选（Q2） |
| 高价值视频低频抽帧 | 整段 10s 视频 embedding，纯 opt-in（Q1/Q3） |
| bge ONNX 进程内推理 | WeMM 就位后完全弃用（Q6） |
| 多模态 512 维截断 | WeMM 维度 N0 验证定（512 截断为初值）；API 验证用 2560 全维 |

不变：native messaging 通道、sqlite-vec 进 flowhub.db、黑名单用户自配 + 密码框整页排除、URL 去重 + 内容哈希、停留 ≥10s 上报、`s ` 前缀全量模式。
