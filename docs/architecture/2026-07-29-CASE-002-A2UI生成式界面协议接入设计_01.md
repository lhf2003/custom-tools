# A2UI 生成式界面协议接入设计

**创建日期**: 2026-07-29
**作者**: LHF（设计裁决）/ Jarvis（实现）
**版本**: v1.0
**状态**: 已批准（spike 验证 + 实测通过）

## 背景

聊天页的回答只能输出文本。Google 2025-11 开源的 A2UI 协议（Agent to UI，v0.9 Stable）定义了 Agent → UI 的流式 JSON 消息格式：模型输出结构化的 UI 描述，客户端用白名单组件渲染，杜绝任意代码执行。本设计将其接入贾维斯场景回退通道，让贾维斯能"递界面"（统计卡片、清单、表单），而非只能"回文字"。

## 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 触发方式 | **工具触发**（render_ui），非模型自主决定 | 零常驻 token 开销，决策显式，与现有 tool-use 循环天然契合 |
| 模型可行性 | spike 验证通过 | qwen3.7-plus 生成合法 A2UI JSON 5/5，结构+语义全对，~2KB 协议摘要即可（无需 46KB 完整 schema） |
| 软引导失败 | **硬性规则 + 工具结果提醒**双转向 | 实测模型忽略"可以画卡片"的软措辞；系统提示改为【界面卡片规则】（数据工具出多条数据必须先卡片后文字）+ 数据工具结果尾部注入提醒（模型注意力最高位） |
| 通道范围 | 仅场景回退通道 | MCP 通道是 Claude Code 终端，没有渲染方 |
| 校验失败 | 原因文本回喂模型自我纠正，单轮限 2 次 | 复用 tool 循环，无需独立重试通道；连续失败劝退保文字兜底 |
| 落库 | 后端 emit 时直接写 `chat_messages(content_type='a2ui')` | 界面消息在 tool 循环中途产生，前端 done 落库时已无上下文 |

## 架构

```
用户提问 → tool-use 循环 → 模型调用 render_ui(surface_id, messages)
    → Rust 校验器（companion/a2ui.rs）
    → 失败：错误文本回喂（≤2 次）
    → 成功：emit jarvis:surface + 落库 content_type='a2ui'
    → 前端按 surfaceId 合并气泡（多次调用=重放语义）
    → 模型继续循环 → 文字总结照旧 jarvis:chunk/done
按钮 action → 前端组装「用户操作+上下文 JSON」代发消息 → 正常发送链路
```

### A2UI 消息模型（v0.9）

- 四种消息：`createSurface` / `updateComponents` / `updateDataModel` / `deleteSurface`
- 组件与数据彻底分离：组件用扁平邻接表（id 互引），数据用 JSON Pointer（RFC 6901）绑定
- 输入组件双向绑定**客户端本地**数据模型，打字不发请求，随 Button action 回传
- `checks` 校验函数（required/regex/email/and/or/not…），Button 校验不过自动禁用

### 后端校验器（companion/a2ui.rs）

首消息 createSurface、18 组件白名单（=前端渲染器能力集）、id 引用闭合（含 List 模板/Tabs/Modal）、root 存在、version 校验；上限 20 消息/100 组件/32KB。同一轮对话内跨调用维护 surface 状态，支持增量更新与 deleteSurface。5 个单测。

### 前端渲染器（src/modules/chat/a2ui/）

| 文件 | 职责 |
|---|---|
| `types.ts` | 协议类型（与后端校验器对齐） |
| `pointer.ts` | JSON Pointer 解析/不可变写入，相对路径模板作用域拼接 |
| `functions.ts` | 15 个注册函数 + formatString `${...}` 插值解析器 + checks 求值 |
| `surface.ts` | 消息重放构建 surface 快照（纯函数） |
| `render.tsx` | 渲染上下文（数据读写/路径解析/action 回传）+ 组件分发 |
| `components/` | 18 个组件全实现：layout（Row/Column/List 模板/Card/Tabs/Divider/Modal）、display（Text/Image/Icon/Video/AudioPlayer）、input（Button/CheckBox/TextField/Slider/ChoicePicker/DateTimeInput） |
| `A2uiSurface.tsx` | 容器：重建 surface、持有本地数据模型、action 组装代发文本 |

### 历史持久化

- `chat_messages.content_type` 新增列（迁移默认 'markdown'）
- 同一 surfaceId 的多次 render_ui 调用在**展示层合并为一个气泡**（消息数组按序重放）；DB 中每次调用一行，天然支持增量与删除的重放
- `load_context` 把 a2ui 历史替换为占位文本「（向用户展示了一张界面卡片）」，协议 JSON 不喂回模型

## 排障记录（实测三轮）

1. **不出卡片**：render_ui 有下发（input tokens +1k 为证），模型两轮工具循环只调数据工具。根因：工具描述只说"能做什么"，没说"什么时候该用"。修复：系统提示软性引导 → 仍失败 → 硬性【界面卡片规则】+ 工具结果尾部提醒，成功
2. **数值折行**：CJK 文本 min-content 仅一字符宽，flex 布局把「2.6 小时」挤压折行。修复：Row 子项包装 `shrink-0`
3. **排版随意**：模型强烈模仿工具描述中的示例——示例从光杆 Column 升级为完整统计卡（含 `justify: spaceBetween` 行模式 + 布局要点），新卡片排版规整

## 成本

render_ui schema 随 tools 列表每轮发送，约 +1~1.5k input tokens/轮（工具触发方案的已知代价），`llm_call_logs.input_tokens` 可观测。
