# 视频整段后台索引交付（N3 体验重构）

**创建日期**: 2026-08-31
**作者**: LHF + Claude
**版本**: v1.0
**状态**: 已交付并 e2e 验证

## 背景

N3 初版「索引画面」只录点击后 10s，整视频需要用户每 10s 点一次，体验极差。
LHF 裁决：点击一次 → **整个视频后台索引**，不打断当前观看。

## 方案（spike 验证后落地）

B站视频流是 dash（fMP4 m4s），页面主世界 `__playinfo__` 可直接拿到播放地址，
CDN 仅需 Referer+UA 头即可直连。因此采集完全绕过「录屏」：

```
点击按钮 → playinfo-probe.js（world:MAIN content script）提取最低码率 avc 流
→ background.js 转交 host → host 立即应答 accepted 并起后台线程
→ sidecar embed_video_url：PyAV HTTP 流式解码（ffmpeg headers 带 Referer），
  10s 窗口水库抽样 24 帧（640×360，内存恒定），逐窗 embed
→ 每段按 seek_url(?t=) 入库 → 扩展每 3s 轮询 VideoIndexProgress 更新按钮进度
```

## 关键设计

- **分块调用**（skip/max_segments，每块 20 段）：块间释放模型锁，前台记忆查询
  不被 10+ 分钟的长索引任务饿死
- **水库抽样**：流式解码不驻留全帧（30 分钟视频 5 万帧装不下内存），
  每窗恒定 24 帧；随机种子定死，重复索引产出一致
- **进度注册表**：host 内存 HashMap<url, VideoJob>，扩展轮询；
  host 重启丢注册表 → 扩展收到 not_found 提示「索引中断」
- **YouTube/探针失败回落**：保留原 10s 录制模式不动
- **SPA 换视频**：停止轮询但 host 作业照跑（后台索引的意义）

## 验证

- spike：`__playinfo__` 提取 ✓（6 条流，最低码率 avc 恰为 640×360）；
  PyAV 带 Referer/UA 直连 CDN 解码 ✓
- e2e（真实 B站 37s 视频）：提交 accepted(total=4) → 轮询 indexing → done=4，
  全程 32s（含模型冷启动）；4 段均为 `?t=` 跳转链接；向量关联完整 0 孤儿
- 扩展三个 JS 文件 node --check 语法通过

## 已知边界

- 多分 P 视频：playinfo 对应当前 P，pageUrl 丢 p= 参数（跳转会回 P1）——暂不支持
- 后台索引无取消按钮（v1）；重复点击只闪示进度不重复提交
- YouTube 走录制兜底（流地址签名复杂，未做后台化）
