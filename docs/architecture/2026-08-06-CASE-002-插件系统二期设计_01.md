# 插件系统二期设计（本地插件市场 + 设置/快捷键贡献点 + AI 生成插件）

**创建日期**: 2026-08-06
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准

## 1. 目标与定位

二期在[一期插件协议](../architecture/2026-08-06-CASE-001-插件系统设计_01.md)之上引入**外部插件**：本地插件市场（手动安装 / AI 生成）+ 设置贡献点 + 快捷键贡献点，协议为**联网市场预留**（不实现联网发现/分发）。

权限模型：**路径 1 信任模型**——外部插件与主应用同权限（`invoke` 全开），首次启用确认是唯一防线；`permissions` 字段预留声明位（不执行校验），权限隔离（iframe 网关或独立窗口 capabilities）在**联网市场开放前**再做。

## 3. 外部插件格式

### 3.1 目录结构

```
app_data/plugins/<plugin-id>/
├── plugin.json          # manifest（必填）
├── plugin.js            # IIFE bundle（esbuild --format=iife，依赖打平）
└── icon.png             # 可选，manifest 的 icon 字段引用
```

### 3.2 plugin.json（外部插件 manifest）

```json
{
  "id": "time-converter",
  "name": "日期转换",
  "version": "0.1.0",
  "author": "LHF",
  "description": "时间戳与日期互转",
  "icon": "icon.png",
  "aliases": ["time", "date", "timestamp"],
  "main": "plugin.js",
  "runtime": "frontend",
  "permissions": [],
  "triggers": [{ "keyword": "@time", "argHint": "时间戳或日期" }],
  "shortcuts": [{ "id": "open", "key": "Ctrl+Shift+T", "label": "打开日期转换" }],
  "settings": [
    { "key": "format", "label": "输出格式", "type": "select",
      "options": ["YYYY-MM-DD", "时间戳", "两者"], "default": "YYYY-MM-DD" },
    { "key": "showSeconds", "label": "显示秒", "type": "toggle", "default": true }
  ]
}
```

### 3.3 IIFE 注册 API

插件 bundle 执行后调用全局注册（uTools 式）：

```js
window.flowhubPlugin = {
  manifest: { /* 与 plugin.json 一致，运行时取用 */ },
  view: {
    mount(container, ctx) { /* 命令式渲染视图 DOM */ },
    unmount() { /* 清理 */ },
  },
  // 可选：renderSettings(container, ctx) —— 复杂插件自绘配置 UI（预留位）
};
```

主应用加载器读取 `window.flowhubPlugin`，适配为标准 `ViewPlugin`。

## 4. 加载机制

### 4.1 生命周期

- **发现**：应用启动时 Rust 扫 `app_data/plugins/*/plugin.json`（`commands/plugins.rs`），返回元数据列表；前端注册表合流（内置 glob + 外部扫描结果）。损坏的 plugin.json 跳过并标记「无效」
- **执行**：bundle 首次打开时才 fetch + 执行（Rust 读文件 → 前端 `new Function` 执行 → 读 `window.flowhubPlugin`）；模块级缓存，切走切回不重跑
- **失败隔离**：bundle 损坏/语法错误 → ErrorBoundary 兜底 + 管理器标记「加载失败」，不影响其他插件与主应用

### 4.2 适配器

外部插件适配为 `ViewPlugin`：
- `load()` → 命令式挂载包装组件（`useEffect` 调 `mount(container, ctx)`，cleanup 调 `unmount()`）
- `icon` → `<img src={convertFileSrc(iconPath)}>`
- 菜单/设置/快捷键 → 从注册的 API 与 manifest 取

PluginHost 与上层零改动，内置/外部无感统一。

### 4.3 启用/禁用

- 状态存 settings 表 `plugins.<id>.enabled`
- 禁用后：启动器不显示、trigger 不响应、bundle 不执行
- 内置插件在管理器显示但锁定（不可禁用/卸载）

## 5. 插件管理器（设置页新 tab）

- **列表**：icon / name / version / 来源（内置/外部）/ 状态（已启用/已禁用/加载失败/快捷键冲突）
- **操作**：启用/禁用开关、打开插件目录（reveal）、卸载（确认后删目录）、快捷键与设置展示
- **信任确认**：首次启用外部插件弹窗——「启用插件「X」？该插件与本应用同权限运行，可访问本应用的剪贴板、笔记、密码等全部数据与功能。来源目录：`app_data/plugins/<id>/`」
- **UI 按 /impeccable 设计评审落地**（DESIGN.md 设计系统为准）

## 6. 设置贡献点

- plugin.json `settings` 声明式 schema：`text | number | toggle | select`（+ default/options/placeholder）
- 主应用自动渲染表单（设计系统统一），存储进 settings 表 `plugins.<id>.<key>`
- **渲染位置（08-07 调整）**：设置页「插件」分组下每个插件一个独立设置 tab（声明了 settings schema 即出现，未启用也可先配置）；插件市场行内展开区已移除，行内「更多 → 设置」跳转对应 tab
- `renderSettings(container, ctx)` 为复杂插件预留（自绘配置 UI），二期不实现主应用侧挂载逻辑，仅保留协议位
- 内置插件配置**暂不迁移**（GeneralSettings 继续集中管理），用户视角统一在设置页

## 7. 快捷键贡献点

- plugin.json `shortcuts` 声明 `{ id, key, label }`
- 启动扫描后一次性注册（`tauri-plugin-global-shortcut` 运行时 register，与内置快捷键同批）；插件目录变更重扫重注册
- action 一期仅支持 `"open"`（打开插件视图）；复杂动作（执行插件命令）后续扩展
- 冲突处理：OS 注册失败（组合键被占用）→ 管理器标记「快捷键冲突」+ 打开插件时 toast 提示；**失败不阻塞插件使用**

## 8. AI 生成插件

### 8.1 管线

插件管理页「AI生成」→ 弹窗输入自然语言描述 → 生成 → 校验 → 预览 → 试运行 → 安装 → 信任：

1. **生成**：描述 + 私有 system prompt → 后端 LLM（**复用 companion 模型配置**，不引入第二套）单次流式生成 `plugin.json` + `plugin.js`
2. **步骤回显**：system prompt 要求按固定步骤链输出（① manifest 框架 → ② 视图逻辑 → ③ 样式（按设计规范）→ ④ 自校验），每步带结构化标记；前端流式解析标记，实时回显「正在生成框架…」等——避免生成长等待的确定性焦虑
3. **校验**：plugin.json 结构校验（schema）+ plugin.js 语法校验（acorn，Tauri 环境无 Node）；失败自动带错误重试 1 次，仍失败报错展示（不写盘）
4. **预览**：文件清单 + plugin.json 摘要 + plugin.js 可滚动代码预览
5. **试运行**：可选按钮，生成的 bundle 在预览容器直接 mount（落临时目录 `app_data/plugins/.preview/`，不列正式列表，关闭预览即清理）
6. **安装**：确认后写入正式插件目录 → 触发扫描 → 出现在管理器/启动器
7. **信任**：首次启用确认框（同手动安装）

### 8.2 私有 system prompt（不对外展示）

- 插件协议规范：plugin.json schema + IIFE bundle 结构 + registerPlugin API
- **设计规范**：DESIGN.md 提炼的「插件 UI 生成规范」（色彩 token / 字体 / 间距 / 组件风格），约束 AI 产出 UI 符合本系统设计
- 安全约束：权限诚实声明、不生成恶意模式
- **私有边界**：只存在于生成调用内部，不进插件产物、不进 UI、不导出、不分发

## 9. 联网市场预留

- manifest 已含 `version` / `author` / `runtime` / `permissions` 字段
- 联网发现、签名校验、更新机制为后续独立阶段；届时权限隔离（iframe 网关或独立窗口 capabilities）与信任确认框升级（权限声明 + 签名校验）同步落地
