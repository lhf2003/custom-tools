# 知识索引插件化裁决（Grill 纪要）

**创建日期**: 2026-09-02
**作者**: LHF / Claude
**版本**: v1.0
**状态**: 已批准

## 背景与动机

启动器内嵌记忆列表（2026-08-27 一期裁决的 D5「C+B」交互：C 分组异步流入 + `s ` 前缀全量模式）在实践中观感不佳：

- 长标题在窄行中截断，tooltip 受控方案接连踩雷（unmount 计时器无清除致浮层闪现即消、`tooltip-base` 的 `white-space: nowrap` 在 utilities 层尾覆盖 Tailwind `whitespace-normal` 致内容截断）
- 视频类型多条分段命中时窄行显示一模一样，时间段被截断，无区分度
- 网页文本同理；图片类型无法预览，用户只能盲猜
- 根源是「把富信息塞进启动器窄行」这个形态本身

**本次裁决推翻 D5 交互条款**（一期裁决其余条款不受影响），知识索引抽离为独立系统内置插件。

## 裁决清单

### 1. 旧形态全部退役，一刀切断

- C 分组（MemoryStrip）退役，由「命中条目」替代；启动器窗口不再撑高 148px
- `s ` 前缀退役，降级为插件 trigger：`s xxx` 直达知识页并预填查询词（PluginTrigger 机制现成）
- 连带清除：`MemoryResults.tsx` 整个删除，tooltip 受控两颗雷随之消失不再修；Tooltip `open` prop 回退（唯一调用方是 MemoryRow）

### 2. 启动器命中条目形态

- 向量检索保留，职责重定义为**命中探测**：k=20（KNN 成本无感，大头在 query embedding），前端按来源聚合，N = 聚合后来源数（与知识页口径一致）
- 命中时条目硬插结果**第一位**（方案 A）：图标 + 「记忆检索」+「N 条命中」，只显示命中数不预览标题
- **选中按 path 锚定不漂移**（复用回车冲刷同款逻辑），防异步突变致盲启动
- 到达时带**缓入动效**（淡入+位移），缓解异步插入的生硬感
- 无命中零占位；折叠态网格满员时挤掉末尾应用（它本来就要展开才可见）
- 回车进入知识页，只传查询词（见裁决 5）

### 3. 知识页聚合模型：来源聚合（方案 B）

- **一来源一卡**：同 URL / 同视频 / 同笔记合并为一张卡，带「N 处命中」角标
- 视频卡片内嵌前 2-3 个命中分段的**时间段 chips**（完整显示 `12:00-14:30`，单独点击直接 `?t=` 跳转，直达性不损失）
- 网页/视频/笔记/剪贴板统一「来源卡 + 命中列表」数据结构，渲染与后处理只有一套
- 卡片信息架构：网页=favicon+标题+top摘要+命中角标；视频=平台图标+标题+时间段chips；图片=favicon/本地预览+来源标题；笔记/剪贴板=标题/摘要+时间
- **能力边界**（一期）：只读检索 + 单条操作（打开/复制/删除单条）；批量管理留设置页，不做
- **空查询态**：显示「最近索引」混合网格浏览视图（按 indexed_at 倒序），让插件不止是检索出口也是记忆浏览入口；统计仪表盘扩展 popup 已有，不重复

### 4. 图片预览：无缩略图管线

图片索引来源仅两个，分别处理：

- **网页来源**：卡片显示**该网页 favicon** 作视觉锚点（识别"哪个站的图"即可，点卡片回原页看真图）。回源加载原图不可行（防盗链/URL 过期/隐私出域）
- **剪贴板来源**：向量化时把**原始文件路径写入元数据**，卡片用本地路径直接渲染真预览
- **零新增存储管线，schema 不动**；原"原始素材不留底"条款维持不变（连 KB 级缩略图也不需要了）
- 边界备案：剪贴板历史过期清理后原图可能已删，卡片渲染需降级占位

### 5. 启动器 → 知识页状态传递

- 只传查询词，页面打开后自行全量检索（k 更大或分页），骨架屏兜住几百 ms 检索延迟
- `s ` trigger 与命中条目点击复用同一通道，单一数据通道、无状态同步问题

### 6. 插件可禁用 + 控制面迁移

- 可禁用（非 essential），禁用只关启动器入口与命中探测；采集/索引管线**不联动**（设置页独立控制）
- **控制面迁移**：`BrowsingPrivacySection`（统计/黑名单/一键清除）+ `LocalModelEnvSection`（WeMM 环境状态灯 + 一键安装）从 `MemoryCenter` 移入本插件设置页
- 记忆事实五维分组 + 习惯模式**留在陪伴设置**（属于贾维斯人格，不属于检索设施）

### 7. 旧代码处置与分期

| 代码 | 处置 |
|---|---|
| `MemoryResults.tsx` | 删除（BiliIcon 挪进知识页视频卡片复用） |
| LauncherView `memorySel` / C 分组撑高 / `s ` 模式 / `memory://` 分支 | 清除，替换为命中探测 |
| Tooltip `open` 受控 prop | 回退删除 |
| Tooltip `activeHide` 全局互斥 | **保留**（应用条目间 hover 仍需单例语义） |
| `memory_search` / `memory_open` 命令 | 保留，知识页复用 |
| `dev-memory-tooltip.html/tsx` | 删除（临时验证页） |

**分期**：

- **P1 核心闭环**：插件注册（入口 + `s` trigger）+ 知识页骨架（搜索框 + 统一聚合模型 + 文本类卡片）+ 启动器命中条目 + 控制面迁移 + 旧代码清除
- **P2 富媒体**：视频分段 chips + 展开层 + 图片卡（favicon 锚点 + 剪贴板路径预览）
- **P3 浏览态**：空查询「最近索引」混合网格 + 视觉 polish

聚合模型必须 P1 统一做好（数据层结构，文本类卡片也走它）；视频/图片只是卡片皮肤。

## 附：GraphRAG 引入分析（结论：不引入）

LHF 提议评估引入 GraphRAG 知识图谱，分析后否决：

1. **场景不对**：GraphRAG 主场是百万级语料的全局 sensemaking 与多跳推理；本系统是个人浏览记忆的**点查找**（千~万级 chunk），向量 + 元数据过滤已是天花板级方案（WeMM 实测 top-3 94%）
2. **成本决定性反对**：索引构建需 LLM 逐文档抽实体/关系——本地小模型质量不达标，API 则隐私出域撞碎二期「全本地为终点」基调；增量图谱更新（每日持续流入）至今无优雅工程方案
3. **已有务实替代**：remember_fact 两级流水线（向量召回 + LLM 裁决）就是按需、增量、带审计的事实沉淀；来源聚合模型（裁决 3）利用元数据天然图结构（同 URL/域名/时间段），无需 LLM 发现
4. **活口**：「轻量关联」路线（元数据图 + 本地 embedding 聚类）可覆盖 GraphRAG 在本场景 80% 价值，成本为零头。**重裁信号**：记忆库 5 万+ chunk 且出现真实的跨主题关联查询需求时，再回来评估
