# 多模态记忆检索系统设计（grill 决策纪要）

**创建日期**: 2026-08-27
**作者**: LHF + Claude
**版本**: v1.0
**状态**: 已批准

## 背景

想法起源：腾讯开源 WeMM-Embedding（[GitHub](https://github.com/Tencent/WeMM-Embedding)，Apache 2.0）支持文本/图片/视频/视觉文档多模态向量，拟将用户访问数据建索引，结合启动器做语义检索（「启动器变成个人浏览记忆的搜索引擎」，Windows Recall 的浏览器子集定位）。

**两个已证实的硬约束**：
1. WeMM-Embedding **不支持音频**（官方明确，MMEB 音频项得分 0）。音频若要做只能 ASR 转文本走文本向量，本设计不含音频。
2. 最小变体 2B 参数，全 Python 栈（transformers/vLLM/SGLang），普通办公本本地跑不现实——一期不能依赖它。

## 决策清单（11 项，逐项已与 LHF 确认）

### D1 索引范围
A（Nervis 已有数据：剪贴板、笔记）打底 + C（浏览器浏览内容）为核心增量。不做全盘文件扫描、不做屏幕截图流。

### D2 采集深度
浏览器扩展上报页面正文（readability 抽取）+ URL + 标题 + 停留时长。不读浏览器历史数据库（只有标题太薄）、不截屏。

### D3 视频策略
- 一期：字幕/标题/简介文本 + 时间戳切段（30-60 秒/段），检索命中跳转 `视频URL?t=秒数`，一期即段落级。
- 二期：高价值视频（收藏/高停留）低频抽帧（~10 秒/帧）走 WeMM 图片向量。DRM 内容 canvas 抓黑帧，物理不可行，明确放弃。
- 「全量视频全量抽帧」不做。

### D4 模型部署
用户自选（本地/云端开关），**默认本地**。一期文本走 bge 级小模型（512/768 维），WeMM（2B）推迟到二期以「可选增强包」形态由用户主动下载。浏览正文默认不出本机。

### D5 检索交互（C+B 组合）
- C：正常输入时应用结果置顶不动，下方「浏览记录/记忆」分组异步流入（2-3 条），回车永远启动第一个应用，Tab/↓ 进分组。
- B：`s ` 前缀进入纯语义全量检索视图。
- 硬约束：query embedding 百毫秒级，语义分组**绝不阻塞主结果**；embedding 推理常驻保活，不现起进程。

### D6 扩展 ↔ 桌面端通道
Native Messaging（stdio，浏览器内核担保），不走 localhost 端口。embedding host 独立 Rust 小二进制兼任 native messaging host：浏览器拉起它 → 向量化 → 写 flowhub.db；主进程不在也能收数据；Nervis 主进程零端口。dev 期可留 `NERVIS_DEV=1` 才启用的 HTTP 调试口，发布版砍掉。

### D7 向量存储与 chunk 策略
- sqlite-vec 扩展，向量直接进 flowhub.db，与 clipboard/notes/浏览记录同库 JOIN。规模估算：重度用户一年 10-15 万条向量（~500MB 含原文），暴力余弦扫描毫秒级，不上 ANN。
- chunk：正文 ~500 字符滑窗（带 URL+标题+时间戳+块序号）；字幕 30-60 秒/段（带起始秒数）。
- 实现期验证点：rusqlite 加载 sqlite-vec 的方式（编译进 vs load_extension）。

### D8 向量维度
文本 512/768 维（bge），二期多模态用 WeMM 512 维截断（Matryoshka，性能保留 ~99%，存储仅全维 1/4）。768 维对 10 万级个人语料区分度充足，维度焦虑是十亿级库的事。float32 存储，后续空间紧张再量化。

### D9 记忆系统向量化（两级流水线，并入一期）
- 向量层做召回：`remember_fact` 写入前 embed，检索 top-k。无命中 → 直接写入，零 LLM 成本（大多数情况）。
- 模型层做裁决：仅命中候选时，「新事实 + top-3」喂小模型判 ADD/UPDATE/NOOP——向量分数对「不是 X 是 Y」类矛盾语义失明，不能单独做判断。
- 阈值不拍脑袋：每次调用落「新事实、命中分数、最终裁决」日志（复用 llm_call_logs 思路），跑两周按真实分布标定。
- 复用同一 embedding 管线和 sqlite-vec 表，零额外基础设施。

### D10 隐私边界（Recall 教训对应）
- 隐身窗口：扩展天然拿不到，零成本免责。
- 敏感站点黑名单：**完全用户自配**（LHF 拍板，无出厂清单）。遗留风险备案：从不打开设置的用户在银行流水页等内容页零保护（登录页由密码框规则兜底），发布前重新评估。
- 密码框规则（不可关闭）：页面存在 `type=password` 输入框 → 整页不索引。
- 保留期：浏览向量默认 90 天滚动删除，设置可调（30/90/365/永久）；笔记/剪贴板不受限（用户主动数据，语义不同）。
- 一键物理删除全部浏览索引 + 按域名删除，不做标记删除。

### D11 去重与更新
- URL 级去重：同 URL 只保留最新索引；正文哈希变了才重 embed（旧 chunk 删除替换）。
- timeline/feed 型页面不索引正文（内容转瞬即逝，无检索价值），可只记 URL+标题。
- 停留 ≥10 秒才触发抽取上报；同页面一次会话只上报一次（SPA 路由跳转算新页面）。

### D12 扩展分发
C → B → A 三步走：开发者模式侧载（内测）→ Edge Add-ons（审核快、Windows 出厂浏览器、定位契合）→ Chrome Web Store（有量后啃）。一期只做 Chromium 系，Firefox/Safari 明确不做。商店隐私披露写「数据仅本机处理」——架构天然满足，是加分项。

### D13 扩展 popup 定位（参考 LHF 提供的设计图）
- 纯状态仪表盘，**不做搜索框**——搜索唯一入口是启动器（C 分组 + `s ` 前缀），避免双入口稀释。
- 四态状态机原样采纳：`已保存 / 处理中 / 仅字幕 / 空缺`（「仅字幕」为一等公民状态，印证 D3 分层）。
- 一期统计行：`页面 / 字幕段 / 队列` + 连接状态徽章；「画面」列二期加回。
- 成本估算行：本地模式显示「本地运行 · ¥0」（隐私卖点广告位），云端开关打开才显示真实计费。
- popup 内放「不再索引此站点」一键加黑名单（最顺手的位置）。
- 视觉按 DESIGN.md 既有 token（panel-glass、violet 主色），不另起风格。

## 技术栈

一期纯 Rust：bge 官方 ONNX 权重 + `ort` crate 进程内推理，零 Python、零额外进程，安装包增量 < 100MB。二期 WeMM 引入 Python sidecar（增强包形态，分发体积争议随用户主动下载消解）。

## 分期与验收

**M0 Spike（1-2 天）**：bge ONNX + ort 中文检索质量验证，真实笔记/剪贴板导出数百条跑描述性查询命中率（照 A2UI spike 先例）。

**一期**：M1 内部管线（sqlite-vec 表、host 骨架、已有数据回填——剪贴板**文本**+笔记）→ M2 浏览器链路（扩展+native messaging+字幕抓取）→ M3 启动器融合 → M4 隐私控制 + 记忆两级流水线。

**一期不做**：剪贴板图片向量、视频抽帧、云端 API、Firefox、出厂默认黑名单。

**二期**：WeMM 增强包 → 图片模态全量解锁（剪贴板图片、页面主图、视频抽帧）+ 云端 API 开关。

**验收线**：
- 描述性查询找一周前文章 top-3 命中率 ≥ 70%（人工评测）
- 语义分组 P95 < 500ms，主结果零阻塞
- 安装包增量 < 100MB，常驻内存增量 < 300MB
- 向量库日膨胀 < 5MB（重度使用）
