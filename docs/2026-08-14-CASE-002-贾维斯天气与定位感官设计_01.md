# 贾维斯天气与定位感官设计

**创建日期**: 2026-08-14
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准（grill 8 项裁决）

## 1. 背景与目标

贾维斯的人格原则是「眼睛是屏幕，屏幕外不编」——这保证了不编造，但也意味着他对屏幕外的世界零感知。本设计给贾维斯装两个**屏幕外感官**：定位（他在哪个城市）与天气（外面什么天气），服务于「真人感」——真人对此刻窗外是「知道」，对明天后天是「查手机」。

数据源：百度地图 Web 服务 API（`location/ip` + `weather/v1`），调研结论见 2026-08-14 会话记录。

## 3. 总体架构

```
┌─ 定时器（tokio interval 30min，companion 启动时 spawn）────────────┐
│  location/ip ──→ city（城市级）                                    │
│  weather/v1 ──→ 实时天气摘要（district=市名+province 辅助）         │
│       │                                                            │
│       ▼                                                            │
│  settings.companion_env_cache（JSON，唯一真源）                     │
│  { city, prev_city, city_changed_at, weather: {...}, fetched_at }  │
│       │                                                            │
│  城市变化 → ① prev_city/city_changed_at 更新（3 天注入提示）        │
│            ② facts 写一条 person 类（source=env_sensor，           │
│               走 remember_fact 同主题覆盖通道）                     │
└────────────────────────────────────────────────────────────────────┘
                          │ 所有触点读同一份缓存
        ┌─────────┬───────┼──────────┬─────────────┐
        ▼         ▼       ▼          ▼             ▼
   聊天动态段  日报prompt  日记素材   晨间卡     get_weather_forecast
   （感官句） （当下状态段） （背景行） （模板行）  工具（7天预报，实时调API）
```

配额估算：单用户 30min×2 接口 ≈ 100 次/天，免费额度无压力。

## 4. 模块设计：companion/envsense.rs（新建）

### 4.1 核心结构

```rust
/// settings.companion_env_cache 的 JSON 结构
pub struct EnvCache {
    pub city: String,               // 「济南市」
    pub prev_city: Option<String>,  // 出差检测：上一个城市
    pub city_changed_at: i64,       // 城市变化时间戳（0=无变化）
    pub weather: Option<WeatherNow>,// 实时天气（采集失败保留旧值）
    pub fetched_at: i64,            // 上次成功采集时间
}

pub struct WeatherNow {
    pub text: String,        // 「晴」
    pub temp: i32,           // 35
    pub feels_like: i32,     // 体感温度（百度 now 返回）
    pub wind: String,        // 「东南风3级」
    pub humidity: String,    // 湿度（注入句不用，工具可用）
}
```

### 4.2 函数契约

| 函数 | 说明 |
|------|------|
| `refresh(app, db_path) -> Result<()>` | 一轮采集：location/ip → weather/v1 → 写缓存。任一步失败**保留旧缓存**只记日志（隐身原则）。城市变化时更新 prev_city/city_changed_at 并写 facts |
| `refresh_if_stale(app, db_path)` | 触点补刷：缓存距今 >30min 才 refresh； blocking 实现（reqwest::blocking），async 调用点用 spawn_blocking 包 |
| `inject_sentence(conn) -> Option<String>` | 读缓存生成聊天/日报/日记共用注入句。**硬切纪律**：无缓存或 fetched_at 距今 >2h 返回 None；城市变化 <3 天追加出差提示 |
| `morning_line(conn) -> Option<String>` | 晨间卡模板行：「济南 · 晴 35°C」，同款 2h 硬切 |
| `forecast(db_path, city: Option<&str>) -> Result<String>` | get_weather_forecast 工具实现：weather/v1 data_type=fc，实时调用（不走缓存），返回 7 天预报文本 |

### 4.3 定时器

companion 启动处（mod.rs）spawn tokio 任务：`tokio::time::interval(30min)`，启动**立即采一轮**（首启无缓存场景），之后按周期。采集失败只记 `log::warn!`，不外抛。

### 4.4 天气查询参数（2026-08-14 真机实测修正）

主通道 **`district_id`（国标 adcode）**：IP 定位实测直接返回 `address_detail.adcode`（且精度可到区县级，如武汉东西湖区 420112；IP 库只到市级时为市级编码），零映射表、零名称歧义。adcode 缺失时兜底 `district=<城市原文>`。

实测修正（与调研文档不符的三点）：
1. **`district` 参数要完整行政区名**：「武汉市」可查、「武汉」报 `status=40 未找到区县`——strip 后缀只用于展示，查询一律用原文；工具按名查询时 status=40 自动补「市」重试一次
2. **`location` 经纬度通道实测免费 AK 可用**（调研文档标为高级权限）——本设计未采用（district_id 更准），留作备用
3. **fc 预报的 `high`/`low` 是数字类型**（解析需兼容字符串形态）

### 4.5 出差 facts 格式

一条 person 类事实：「他最近在青岛（8 月 14 日起，可能在出差/旅行）」。写入走 db 层 remember_fact 同路径（bigram 去重覆盖），source 记 `env_sensor`。回程（城市变回）时再写一条「他回济南了」，覆盖机制自动顶掉旧条目。

## 5. 注入设计（四触点）

### 5.1 聊天（compose_chat_system 动态段，挂「当下状态」区）

```
# 你的窗外
你住在他的电脑里——他现在在济南，此刻外面：晴，35°C（体感 38°），东南风3级。
（今天 14:05 采集。这是你的亲身感知：说体感不报数据——「外面挺热的」，
不是「当前温度35°C」。定位只到城市级：哪个区、在不在家，你不知道也不猜。
数据超过2小时没更新就别当真。）
他最近从青岛回了济南——出差/旅行相关的话头可以自然带。
```

- 挂位：动态段末尾区（时间/状态句/时间桥之后），前缀稳定段不受影响
- 补刷：scene_chat.rs 两处调用点（async）在 compose 前 `spawn_blocking(refresh_if_stale)`；`jarvis_chat_system` command（同步）直接调 `refresh_if_stale`（过期才网络阻塞 ≤2s，新鲜时零成本）

### 5.2 日报（run_scene_report「当下状态」段追加同款句）

reporter.md 蛐蛐规则加一条：**天气可入蛐蛐，说体感不报数据**（「大热天他还跑了一下午外勤」）。正文保持专业不带天气。

### 5.3 日记（diary.rs 素材区加天气背景行）

diary.md 素材规范加一行格式：`当日天气：晴，最高 35°C（济南）`。日记私有，允许数据格式（蒸馏进 attitude 时自然消化）。

### 5.4 晨间卡（check_morning_digest body 第一行）

Rust 模板：`济南 · 晴 35°C\n` + 原有「今日关注/备忘待办」。纯客观零小剧场（Toast 铁律），不经模型。

## 6. 工具设计：get_weather_forecast

```rust
ToolDef {
    name: "get_weather_forecast",
    display_name: "天气预报",
    group: ToolGroup::Perception,
    core: false,        // 非核心：关了人格不残缺，用户可在工具页禁用
    external: false,    // 对内：外部客户端自己调百度即可
    description: "查询未来7天天气预报（日期/天气/温度区间/风力）。他不问就不查——
                  此刻的天气你本来就知道（见「你的窗外」），这个工具只用于
                  「明天/周末/下周会下雨吗」这类未来问题。没有逐小时、预警和生活指数。",
    input_schema: { city: Option<String> /* 默认当前定位城市 */ },
}
```

- 实现：weather/v1 `data_type=fc`，实时调用不走缓存
- 能力边界写死在 description 里——防止模型答应做不到的事（「我看看预警…调不了」）
- tools.rs 现有 20 工具 → 21；MCP 对外 tools/list 不受影响（external=false 过滤）

## 7. 降级矩阵（全场景静默隐身）

| 场景 | 行为 |
|------|------|
| 无网/接口挂/配额烧穿 | refresh 失败保留旧缓存，只记日志；旧缓存超 2h 后注入句自然消失 |
| 首次启动无缓存 | 定时器启动立即采一轮；采到之前所有触点无注入 |
| 缓存 >2h（补刷也失败） | `inject_sentence`/`morning_line` 返回 None，工程侧硬切 |
| AK 未注入（dev 环境未配 env） | `option_env!` 为 None → refresh 直接跳过，整体能力隐身，编译不报错 |
| 城市定位失败但天气成功 | 不会出现（weather 依赖 city，city 失败则整轮失败） |

## 8. 安全

- AK/SK 编译期 `option_env!` 注入：本地 dev 走 `.cargo/config.toml` `[env]`（gitignore）或系统环境变量；CI 走 GitHub Secrets；**不进入任何前端产物**（Rust 侧常量，WebView 不可达）
- 控制台开 SN 强制校验：裸 AK 被提取也调不通，盗用需逆出 SK（编译产物字符串提取，门槛高于 JS 明文）
- 已知残余风险（LHF 知情）：SK 终究在二进制内，可被逆向；缓释=控制台配额上限+异常调用人工监控
