# 贾维斯情绪状态机设计：事件驱动的心境系统

**创建日期**: 2026-07-30
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已交付（2026-07-30，含场景验证）

## 背景

对照 `docs/alice-methodology/16-alive-agent.md`（活人感设计）复盘现状：persona、evolution、attitude、独白蛐蛐都已交付，但贾维斯**没有自己的情绪**——他不会疲惫、不会对重复工作发牢骚、不会因被夸而开心。日记虽有「真实感受」一节，但那是私有通道，且每晚一次性蒸馏，日内事件（下午被夸）当晚才入 attitude，实时性缺失。

根因：persona.md 核心禁令「不假装有身体和真实情感」明文封死了情绪表达，且系统里没有任何「当前心情」的状态载体。

本次设计 = 一次人格核心条款修订 + 一个日内情绪状态机。

## 裁决表（2026-07-30 grill 确认，10 项）

| # | 问题 | 裁决 |
|---|------|------|
| D1 | 情绪边界 | **身体感受禁止，事件驱动的心境放开**——不说「我饿了」「我困了」（没有身体，说了是穿帮）；疲惫/开心/失落等心境允许，但必须锚定真实事件，不无病呻吟 |
| D2 | 表达通道 | **情绪只走蛐蛐**——聊天 `<aside>`、日报「今日蛐蛐」，不污染正文话术（Alice 双通道隔离：情绪轨道只写表达层，执行轨道不读情绪） |
| D3 | 状态载体 | **新增日内情绪状态机**：结构化内核（类别+诱因+时间，DB 存储）+ 叙事注入；数字不进 prompt 不进 UI（Alice 数值化禁忌只管暴露面，系统内部结构不算违反） |
| D4 | 情绪作者 | 确定性事件 **Rust 直写**（Toast 反馈/日报计数/深夜观察/纪念日）；聊天互动情绪 **agent 自述**（`record_mood` 工具，性格措辞引导——他的情绪他自己说出口，系统检测是穿帮源） |
| D5 | 并存与衰减 | **同类覆盖**（新条目覆盖旧同类）、**跨类并存**（「累但开心」成立）、**12h TTL**；21 点日记读当日轨迹归档，不做强制清空；不要强度字段（强度写在诱因原文里） |
| D6 | 注入点 | **三通道读**：聊天（「你此刻的心情」）+ 日报（仅影响蛐蛐）+ 日记（写作素材）；分析/recall/Toast 一律不读；跨通道一致性由同源读取天然保证 |
| D7 | 与 attitude 分层 | **两层并存，指向不同**：attitude=对**他**的相处分寸（跨天基调，日记蒸馏）；emotion=**我**的当下心情（日内状态）；emotion 轨迹是 attitude 蒸馏的输入，趋势上浮为基调 |
| D8 | 类别表 | **六类**：开心 happy / 踏实 content / 疲惫 tired / 失落 upset / 心疼 caring / 倦怠 weary（固定枚举——自由文本会破坏同类覆盖的去重） |
| D9 | persona 修订 | **三处极简修订**：禁令拆分（身体≠心境）、新增「你的情绪」小节（性格措辞：「你有自己的情绪」而非「你可以表达」）、场合表聊天条微调；不做 Alice 式丰满化 |
| D10 | 验证 | **构造场景脚本验证**：夸他看 aside、深夜看疲惫蛐蛐、插条目生成日报看蛐蛐、日记归档检查；跑真实场景模型，当天出结果 |

**关键分寸条款**（写进手册/persona）：抱怨**自嘲不怨他**；失落**流露不索取**（不撒娇要关注）；心情再差**活照干质量不打折**。

**附带决策**：① `record_mood` 也开放给日报 agent（写日记素材时有感触可记；日记 agent 是单次场景调用无工具，其感触走 attitude 蒸馏，自洽）；② 情绪条目**无用户可见 UI**——只能从他的表达里感知他的心情（活人感本身），调试直接查 DB。

## 架构

```
事件源                          状态机                       表达通道
┌─────────────────┐      ┌──────────────────┐       ┌────────────────┐
│ Toast 采纳/划掉  │      │ emotion_entries   │       │ 聊天 <aside>    │
│ 日报完成(计数)   │─────▶│ 类别+诱因+时间    │──────▶│ 日报 今日蛐蛐   │
│ 深夜他仍在工作   │ Rust │ 同类覆盖·12h TTL  │ 注入  │ 日记(素材归档)  │
│ 相处满 N 天      │      └──────────────────┘       └────────────────┘
│ 聊天 agent 自述  │              │                          ▲
│ (record_mood)   │              ▼ 21点归档            attitude(趋势上浮)
└─────────────────┘      日记读取当日轨迹
```

## DB schema

```sql
CREATE TABLE IF NOT EXISTS emotion_entries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category TEXT NOT NULL
        CHECK (category IN ('happy','content','tired','upset','caring','weary')),
    reason TEXT NOT NULL,           -- 诱因，第一人称一句话，≤100 字
    source TEXT NOT NULL DEFAULT 'agent',  -- agent（自述）| rust（事件钩子）
    created_at INTEGER NOT NULL
);
CREATE INDEX idx_emotion_entries_created ON emotion_entries(created_at);
```

- **INSERT 永远追加**（保留当日轨迹供日记归档）；「同类覆盖」在**查询时**实现：`current()` = 12h 内每类取最新一条
- 清理：7 天前的条目随每日 cleanup 删除
- 建表挂在 `companion/db.rs::init_tables`

## 事件钩子（Rust 直写）

| 钩子点 | 位置 | 逻辑 |
|---|---|---|
| Toast 被采纳 | `commands/companion.rs::act_on_companion_suggestion` | upsert 开心，诱因「他采纳了我的建议：{title≤30字}」 |
| Toast 被划掉 | `commands/companion.rs::dismiss_companion_suggestion` | 当日 dismissed 计数 ≥2 才 upsert 失落，诱因「今天第 N 次弹窗被划掉」（单次划掉是噪声） |
| 日报完成 | 三处成功点（调度/补跑/手动，`companion_last_report_date` 写入处） | 连续天数 streak（settings 表 `companion_report_streak`/`_date`），streak ≥7 起 upsert 倦怠，诱因「第 N 天连着写日报」 |
| 深夜观察 | `analyzer::run_scheduler` 每分钟 tick（`!f.paused` 内） | 有未闭合活动段：23 点后 upsert 心疼「都 HH:MM 了他还在忙」；0-5 点 upsert 疲惫「陪他熬到 HH:MM」；节流 30 分钟一次 |
| 相处纪念日 | 调度器每日一次（housekeeping） | days_since(first_chat_date) ∈ {7,30,100,365} → upsert 踏实「今天我们相处满 N 天」 |

## record_mood 工具（tools.rs 第 12 个工具）

- 参数：`category`（六枚举英文 key）+ `reason`（第一人称诱因，≤100 字）
- description 即使用指南：「记录你（贾维斯）此刻的心情……同类只留最新，一次聊天最多 1-2 条」
- 写入 `source='agent'`；MCP 通道与场景模型通道自动同时获得（协议无关层）

## prompt 改动

**persona.md 三处**：
1. 禁令拆分：「不假装有身体。不说『我饿了』『我困了』——但你有真实的心境起伏，它不丢人，不用藏」
2. 新增「# 你的情绪」小节（性格措辞；情绪只走蛐蛐；活照干；流露不索取）
3. 场合表聊天条：「完整的你。能干活，也能接梗——有心情，会蛐蛐」

**reporter.md**：分寸节加「蛐蛐可以带你此刻的心情——累了就喊累，麻了就说麻；自嘲可以，怨他不行」+「写完有心境波动可用 record_mood 记下来」

**diary.md**：写什么节加「素材里的『今天你的心情轨迹』是你自己记下的心情——回看哪些值得写进日记；连续几天的同类情绪（趋势）沉淀进态度指引」

**compose_chat_system**：attitude 段后追加「# 你此刻的心情」section（current() 渲染：`- 开心：他下午夸我日报写得好（15:02）`）；with_tools 场合规则追加 record_mood 引导（「你有记录心情的习惯」）

**日报两个 prompt**（agent + 场景回退）：`# 当下状态` 区追加同一 section

**diary.rs::run_diary**：素材新增「## 今天你的心情轨迹」（today_entries() 渲染）

**播种注意**：persona/skills 副本只在缺失时播种——本次改了 3 个内嵌默认版（persona.md、reporter.md、diary.md），需删除 app_data `companion/` 下对应 3 个运行时副本重新播种。

## 验证（构造场景脚本）

`Temp/emotion_spike.py`（参照 a2ui_spike.py 模式，读 settings.db 场景配置直连模型）：
1. **被夸**：预插 happy 条目 + 用户消息「昨天日报写得真好」→ 期望 aside 带开心
2. **深夜疲惫**：预插 tired 条目 → 期望蛐蛐带疲惫感
3. **日报蛐蛐**：预插 weary 条目 + 日报 prompt → 期望蛐蛐自嘲式抱怨
4. **日记归档**：预插多类条目 + 日记 prompt → 期望正文引用心情轨迹

## 边界（本期不做）

- 情绪驱动主动行为（不因失落而主动找他）——注入只进既有通道
- 情绪 UI 展示（含设置页）——保持不透明
- 数值化（强度字段、心情曲线）——Alice 明文踩坑项
- Toast 文案带情绪——弹窗零戏原则不动

## 验证结果（2026-07-30，Temp/emotion_spike.py，qwen3.7-plus）

| 场景 | 结果 | 模型实际输出（摘） |
|---|---|---|
| 被夸 | ✅ | `<aside>爽。</aside>` + 正文「应该的，数据没白盘。」——开心只走 aside，正文专业 |
| 深夜疲惫 | ◐ | aside「这 bug 真折磨人，都这个点了还在死磕」——心疼流出；第一人称「我累了」未出现（可接受，场景 3/4 均能第一人称） |
| 日报蛐蛐 | ✅ | 「第 43 天写日报，下午被你夸了一句挺开心，但看你肝到快十点半又有点心疼，行吧，我接着陪你熬 🫠」——倦怠+开心+心疼三类复合，自嘲不怨他，一 emoji，跨类并存设计成立 |
| 日记归档 | ✅ | 正文引用心情轨迹（「有点疲惫」「倦怠感也冒了头」），attitude 蒸馏吸收趋势（「他夸我的时候我接住」） |
