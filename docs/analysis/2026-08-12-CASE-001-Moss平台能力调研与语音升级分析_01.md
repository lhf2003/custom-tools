## 2. 平台定位

Moss 开放平台是 OpenMOSS 团队(开源 MOSS 系列模型)的商业化 API 服务,定位**多模态音频 AI**,能力全部围绕语音(TTS / ASR / 音色)。

- API 基址:`https://api.mosi.cn/v1`
- 鉴权:`Authorization: Bearer <API_KEY>`,Key 在控制台「API Key 管理平台」创建,仅创建时完整展示
- 风格:REST,`/v1/audio/speech` 与 OpenAI 同构;严格入参校验(未知字段返回 400);Key 无效可能返回 403 而非 401
- 计费:积分制(Mossland & MossAPI)
- 交付:同步直返 / `async=true` 异步任务(`task_id` 轮询 `GET /v1/audio/tasks/{task_id}`)/ `webhook_url` 回调(需公网 HTTPS)

## 3. 能力清单

### 3.1 语音生成(TTS 方向)

| 能力 | 端点 / 模型 | 关键特性 |
|---|---|---|
| 单人 TTS | `POST /v1/audio/speech`,MOSS-TTS-v1.0-Pro / v1.5-Flash | `voice_id` 选音色(仅接受 ID,不接受 url/base64);mp3/wav/pcm;`delivery_method=audio`(默认,二进制直返)/ `url`(JSON+结果URL) |
| 流式 TTS | 同端点,`version=flash-20260626` + `stream=true` | 低延迟;`stream_format=sse` 返回 SSE(base64 PCM delta,事件:`task.created`/`speech.created`/`speech.audio.delta`/`speech.audio.done`/`error`),省略则返回原始 PCM 字节流;`speed` 0.25–4;`language` 语言提示;仅支持 pcm;不与 async/webhook 同用 |
| 多人对话语音 | `POST /v1/audio/speech/speakers`,MOSS-TTSD | 播客/对话式多角色合成 |
| 音色设计 | MOSS-VoiceGenerator,`POST /v1/audio/voice/generations` | 用文本描述生成音色/按声音指令生成语音 |
| 音色克隆 | `POST /v1/audio/voices` | 仅 multipart/form-data,`audio_sample` 字段上传参考音频 → 可复用 `voice_id`,供 TTS/TTSD 引用 |

### 3.2 语音识别(ASR 方向)

| 能力 | 模型 | 关键特性 |
|---|---|---|
| 音频转写 | moss-transcribe | 同步返回 `{ text }`;输入源 `file`(multipart)/`file_id`/`url`/`audio_url` 四选一;单文件最大 512MB;支持 AAC/AMR/FLAC/M4A/ALAC/MOV/MP3/MP4/MPG/OGG/OPUS/WAV/WebM/WMA(含视频容器) |
| 多说话人转写 | moss-transcribe-diarize | `diarize=true` 返回 `segments[]`(含 `start`/`end`/`text`/`speaker` 如 S01);`version=v20260410-streamparam-20260703` 支持 `stream=true` SSE 流式转写 |

### 3.3 基础设施

- `GET /v1/models` 模型列表;`/v1/files` 文件上传/列表/详情/删除(先上传得 file_id 再引用)
- `aigc_metadata`:可选在生成音频中写入 AIGC 隐式标识(合规,对外分发建议开启)
- 异步任务统一经 `task_id` 查询或 webhook 交付

## 4. 本项目现状(2026-08-12 核实)

- 聊天 `src/modules/chat/`:纯文本流式对话 + A2UI 生成式 UI,多提供商 LLM 配置(ModelSettings)
- 陪伴 `src/modules/companion/` + `src-tauri/src/companion/`:贾维斯人格(persona.md)、toast 主动关怀弹窗、记忆/心情/建议/日报/调度器
- **零语音能力**:grep `tts|speech|voice|audio` 仅命中剪贴板音频后缀分类、记忆分类名 "voice"(表达偏好)、A2UI 组件名 AudioPlayer,均非真实语音合成/识别

## 5. 升级点分析

### 5.1 陪伴功能(收益最大:贾维斯"开口说话")

1. **toast 语音播报**(核心):主动关怀弹窗(久坐提醒、日报完成、建议)由纯文字升级为流式 TTS 语音,SSE 边收 PCM 边播,弹窗出现即发声。
2. **贾维斯专属音色**:音色设计(文本描述如"沉稳温和的男声管家")或克隆参考音频,`voice_id` 固化到 settings;人格从 persona.md 文字延伸到声音,差异化能力。
3. **心情→声音映射**:`record_mood` 六类心情(happy/content/tired/upset/caring/weary)以语速(0.25–4)+ 音色变体外化。
4. **"听日报"**:日报长文本走异步任务(task_id 轮询),生成语音版日报。
5. **TTSD 播客式周报**:多人对话模型把周总结合成对话式播客,可与 A2UI 已有 AudioPlayer 组件衔接。

### 5.2 聊天功能

1. **语音输入**(已排期实现):麦克风录音 → moss-transcribe 同步转写 → 文字填入输入框。WebM/OPUS 均在支持格式列表,MediaRecorder 产出可直接上传。
2. **回复朗读**:LLM 流式文本按句切分喂流式 TTS,边生成边播。
3. **会议纪要 → 笔记**:512MB 音视频 + 说话人分离(带时间戳/speaker 标记)→ LLM 管道总结 → 落 markdown 笔记,聊天/笔记/Moss 三方联动。

### 5.3 工程接入要点

- 桌面应用无公网地址,**异步不用 webhook,一律 `task_id` 轮询**
- API Key 存储复用现有 AES-GCM 密码存储或 settings 表;调用日志并入 `llm_call_logs` 观测体系
- 流式 PCM 播放两条路:Rust 端接收 + rodio 播放(推荐,不阻塞 WebView);或转发前端 Web Audio API
- Tauri 前端直接 fetch api.mosi.cn 会受 CSP/ CORS 约束,统一走 Rust 命令中转,与现有 LLM 调用同构
