关键读数：

1. **top-3 三家持平 88%，bge top-1 领先**——一期漏检主因（时间/元数据歧义）在三个模型上复现，证实漏检是语料特性而非模型差距；N1 的时间衰减 + 元数据过滤设计仍然必要。
2. **qwen3-vl 查询侧 instruct 是必需品**：裸文本 81% 未过线，加「为这个句子生成表示以用于检索相关的个人记忆、笔记与剪贴板内容」后 88%。云端模式落地时 instruct 写死在查询链路。
3. **WeMM 裸查询即达 88%**，无需指令前缀；MRL 截断到 512 直接掉出红线（81%），**维度裁决改为 2048 全维**（float32 8KB/条，10 万条 800MB，可接受；一期裁决的 512 截断假设作废）。
4. **WeMM 未命中明细（2048d）**：IVR kubectl（clip-10362 vs 期望 note-ivr.md#0）、燃气 curl（clip-10743 vs 期望 clip-10754）——后者在三个模型上全军覆没，属于语料级歧义难题。

## 环境坑记录（N1 落地必须绕过）

1. **HF 镜像须禁 xet**：`HF_HUB_DISABLE_XET=1`，否则模型权重走 xethub 后端 401（镜像不代理）。
2. **torchvision 必装**：缺失时 video processor 在映射表里被静默置 None，AutoProcessor 加载炸 `TypeError: NoneType is not iterable`，报错信息完全无指向性。
3. **trust_remote_code=True 必须显式**：transformers 5.2.0 主线能加载 `qwen3_5` 架构但得到裸 `Qwen3_5Model`，无 `embedding()` 方法；不报错不警告，调用时才炸。
4. **batch 必须 padding=True**，且 padding 后 batch 内 embedding 与单跑余弦 = 1.0，位置提取正确（已验证）。
5. **GPU 显存**：fp32 需 8GB+ 超 RTX 5060 Laptop（8GB），bf16 占用 5.1GB 可行；bf16 回归数据即本报告数据。
6. **Windows PyPI torch 是 CPU 版**：CUDA 版须走 download.pytorch.org/whl/cu128 官方源（PEP503 完整）；阿里云 pytorch-wheels 镜像有文件但非 simple 布局 pip 不可用，清华镜像无 cu128 通道。
7. **qwen3-vl API 视频下限 24KB**：静态图转视频压不出码率会触发 `video size should be [24KB, 50700KB]`，样本须加动态内容。
8. **WeMM 基座是 Qwen3.5**（`Qwen3_5ForConditionalGeneration`），Matryoshka 档位 64/128/256/512/1024/2048。

## 结论与建议

- **双轨 go**：API 轨验证了检索质量与视频链路（2560 全维，验证使命完成）；WeMM 轨 2048d 过红线且全本地、延迟优于 API。
- **N1 按裁决开工**：WeMM 2048 全维建正式空间，存量 bge 数据全量重 embed。
- **建议 N1 附带 CPU 基准**：若 CPU 全量 embed 耗时过长（>30min/488 条），N1 的存量重 embed 任务需做闲时调度与断点续跑。
