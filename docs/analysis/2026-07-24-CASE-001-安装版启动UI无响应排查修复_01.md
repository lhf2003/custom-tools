# 安装版启动后窗口不显示/托盘无响应排查与修复

**创建日期**: 2026-07-24
**作者**: LHF + Claude
**版本**: v1.0
**状态**: 已修复

## 问题现象

用户通过 NSIS 安装包安装 FlowHub 后启动：

- 快捷键（Alt+Space 等）被软件占用，但按了页面不显示
- 双击、右键右下角托盘图标均无反应（右键菜单不弹出）
- 进程活着，剪贴板监听正常记录日志

## 诊断过程

用户日志关键断点：

```
17:05:58.056 Registered shortcut ... (6 条快捷键全部成功)
17:05:58.059 Clipboard watcher started
—— 之后静默 ——
17:06:23.249 Clipboard update detected (watcher 独立线程,照常工作)
```

setup 后续必有的日志全部缺失：`Loaded N applications from cache`、`Registry scan found`、`UWP scan found`、`Companion module started`。

**结论**：setup 卡在 `lib.rs` 的 `search_index.load_from_cache()` → 无缓存时同步执行 `index_apps()` 全量索引。setup 运行在主事件循环线程上,阻塞即消息泵停摆,导致窗口/托盘/快捷键全部无响应;剪贴板 watcher 是独立线程所以不受影响。

**环境相关的卡死点**（同步索引路径上,按嫌疑排序）：

| 位置 | 机理 |
|---|---|
| `registry.rs` `exists()`/`read_dir()` | DisplayIcon/InstallLocation 指向断开的网络盘时每次调用阻塞数十秒,Uninstall 键下几十个此类条目 ≈ 永久卡死 |
| `scan_directory` 递归 | 桌面/开始菜单重定向到网络位置时 `read_dir` 阻塞;junction 可导致无限递归 |
| `uwp.rs` `cmd.output()` | PowerShell 无超时,企业 EDR/组策略可挂起 powershell.exe |

**结构性根因**：带外部环境不确定性的全量 I/O 同步跑在 setup 主线程。

## 修复内容（P0 + P1)

### P0 结构修复
1. **首次索引挪出 setup 主线程**(`lib.rs`):setup 只创建空 `SearchIndex` 并托管状态;后台线程先 `load_from_cache`(只读本地 SQLite,持锁无碍),无缓存则 `collect_all_apps` 全量扫描——**扫描不持锁**,完成后 `apply_indexed_apps` 短暂持锁交换结果。
2. **搜索命令 try_lock 降级**(`commands/search.rs`):`search_apps`/`get_recent_apps` 索引忙时返回空结果;`refresh_apps` 返回"索引更新中"提示。避免 sync command(主线程执行)等锁再次卡死 UI。

### P0 单点加固
3. **PowerShell 调用加 10s 超时**(`uwp.rs`):`spawn` + stdout/stderr 独立读取线程(防 pipe 缓冲阻塞)+ `try_wait` 轮询,超时 kill。
4. **注册表扫描跳过网络路径**(`registry.rs`):新增 `is_remote_path`(UNC 前缀 + `GetDriveTypeW == DRIVE_REMOTE`),跳过其 `exists()`/`read_dir()`。
5. **目录扫描防 junction 循环**(`mod.rs`):用 `DirEntry::file_type()`(不跟随链接)判断,跳过 junction/symlink 目录;最大递归深度 5;单个子目录失败仅 warn 不拖垮整体;UNC 顶层目录直接跳过。

### P1 可观测性
6. **日志插件前移**(`lib.rs`):从 setup 内挪到 Builder 链首位,`TargetKind::LogDir` 自动解析日志目录。此前托盘/updater 初始化失败留不下任何日志。
7. **panic hook 落盘**:`run()` 开头安装全局 hook,panic 写入日志 + 直接追加 `logs/panic.log` 兜底(GUI 子系统 panic 默认无声)。
8. **setup 分步日志**:db/settings/clipboard/search/companion 各阶段及 "Application setup completed" 均有 info 日志,今后用户机器再卡可精确定位断点。

## 行为变化

- 首次启动后几秒内,搜索可能只有缓存结果或为空(后台索引完成前),UI 全部正常。
- 索引环境再恶劣(网络盘断开、PowerShell 被挂起),窗口/托盘/快捷键也不再受影响。

## 遗留观察点

- 若用户机器索引仍慢,新日志中 "Background initial app indexing started" 后无 "finished",配合 Registry/UWP scan 日志与 UNC/超时 warn 可定位具体卡死源。
- `refresh_in_background` 仍在后台线程持锁执行(`refresh_apps` 手动刷新路径),未改为无锁扫描;如后续成为瓶颈再重构。
