## 一句话结论

Alice 与陪伴功能是**同命题、不同数据源**的两个产品：他的记忆来自**对话**，我们的来自**窗口活动流水**。四章读下来，我们的架构骨架（权限、记忆、白名单、边界）与他高度同构且多处已对齐；**真正可移植的增量集中在两个 prompt 层的小改**，外加一个需要产品拍板的人格化方向。

## 第七章 · 权限系统 → 对照「毕业制」

Alice：五种权限模式（plan/default/accept_edits/dont_ask/bypass）+ 规则匹配 + AI 分类器 + 拒绝追踪，每个决策携带 `reason` 可审计。

我们：毕业制状态机（学习期 → 接受×3 毕业 / 忽略×2 降频 / 拒绝×2 停用）。

| Alice 的做法 | 我们现状 | 判定 |
|---|---|---|
| 每个权限决策带 `reason`（user_allow/rule_allow/ai_safe…）可审计 | suggestions 有 status 但**没记录状态迁移的原因与来源** | **可移植（P2）**：给毕业制迁移记 reason（user_accept / auto_graduated / ignored_cooldown / dismissed_disabled），调试「这条模式为什么毕业了/停用了」时有据可查 |
| 拒绝追踪：被拒操作摘要注入 system，防 AI 反复碰壁 | 忽略×2 降频、拒绝×2 停用，已内建等价机制 | 已对齐，无需动 |
| 「改变自己 vs 改变用户系统」分级（~/.alice 写操作自动放行） | MCP `write_note` 限定「陪伴日报」目录 + 自动执行只到「打开应用」 | 已对齐（同一原则） |
| AI 分类器兜底危险操作 | 规则毕业制，无语义分类需求 | 不适用 |
| plan 模式（只规划不执行） | 陪伴不执行复杂任务链 | 不适用 |

## 第五章 · 上下文与记忆 → 对照「记忆层」（增量最大）

Alice：四层压缩（对话内）+ 五层记忆（跨会话 M1 在线/M2 项目/M3 向量/M4 结构化/M5 用户画像）。

我们：activity_log（事件流水）+ memory_facts（单层持久事实，category=person/project/preference/general + confirmations 去重强化）。

| Alice 的做法 | 我们现状 | 判定 |
|---|---|---|
| **记忆提取的边界判断**：该存=约定/非显而易见的决策/踩坑；不该存=可从代码查到的、临时状态、人格指令、隐私 | 每日分析 prompt 提取 facts，但**没有写「不该存」的负例规则** | **可移植（P1，零成本）**：把「不该存」清单写进 `build_analysis_prompt`——纯 prompt 改动，直接提升 facts 质量 |
| **用户画像三维分离** identity/workflow/voice，因更新粒度不同而分文件维护 | category 四类（person/project/preference/general），语义与之近似（person≈identity、preference≈voice、project≈workflow） | **可移植（P2）**：分析 prompt 按三维引导提取（保留现有 category 存储不变，只改提取引导），让「你说话的风格/禁忌」这类 voice 事实也能沉淀 |
| 向量记忆**对话结束后才写入**，防「把自己刚说的话当历史召回」的自我强化循环 | 分析只读昨日 activity_log 历史数据，无对话场景 | 天然规避，无需动 |
| 「记忆是添加了就一直有用的知识，不是事件日志」 | memory_facts 定位一致（events 在 activity_log，facts 在 memory_facts） | 已对齐 |
| 四层压缩（Snip/MicroCompact/Collapse/AutoCompact） | 无多轮长对话场景 | 不适用 |
| 压缩互斥守卫 | scheduler 单线程顺序执行 | 不适用 |

## 第九章 · Skill 系统 → 对照「行为链学习 + agent 边界」

Alice：Markdown + frontmatter 描述工作流，`when_to_use` 语义触发，`allowed_tools` 最小权限，项目级覆盖用户级，用后自动分析改进（用户确认才落盘）。

我们：行为链三种模式（数据匹配触发）+ MCP `--allowedTools` 白名单 + 毕业制用户确认放权。

| Alice 的做法 | 我们现状 | 判定 |
|---|---|---|
| `allowed_tools` 最小权限白名单 | agent 运行 `--allowedTools "mcp__companion__*"` | 已对齐 |
| Skill 改进「AI 建议 → UI 展示 → 用户确认 → 落盘」闭环 | 毕业制「请示 → 投票 → 放权」闭环，同一精神 | 已对齐（我们更激进：票数够自动毕业） |
| `disable_model_invocation`：高权限 Skill 只显式调用 | 自动执行只到「打开应用」，不碰凭证 | 已对齐 |
| `when_to_use` 精确触发描述（含「不适用于」负例） | pattern description 为模板化字符串 | 可移植（P3）：让 LLM 产 pattern 时顺手写「何时适用/何时不适用」，提高设置页可读性——收益小，缓做 |
| 项目级 Skill 覆盖用户级 | 单用户单产品 | 不适用 |

## 特别章 · 活人感设计 → 对照「主动秘书」定位

Alice：设定集（Character Bible）作为工程文档，PROTECTED 分区保护核心身份，`<response>` 正式回答与 `<aside>` 内心小剧场两个表达空间，子 Agent 全人设。

我们：系统腔文案，无人格设定；信条「信噪比 > 智能，被无视 = 死亡」。

| Alice 的做法 | 我们现状 | 判定 |
|---|---|---|
| 设定集（性格/背景/禁忌）作为工程文档 | 无人格设定 | **需产品拍板**：是否给陪伴一个轻量设定（名字/语气/禁忌）。注意与我们的信条天然张力——人味越多越容易被无视 |
| `<response>` 专业 + `<aside>` 人味小剧场双空间 | 日报与建议卡均为单一专业腔 | **可移植（P2）**：日报 prompt 加 aside 空间——正文保持专业，结尾允许一句轻量人味（如「今天 IDEA 又开了 6 小时」）。**只在日报里加，Toast 不加**（打断场景人味=噪音） |
| 记忆可见、可编辑、可回滚 | 设置页可见可删 ✓（无回滚，删除即目的） | 已对齐 |

## 我们领先 / 他没有对应物的部分

- **意图暂存「记」+ 三条归还通道**（晨间/关键词/渠道）：他没有对应机制，他的记忆偏对话沉淀
- **毕业制用脚投票**：他的权限是预设模式（用户选档），我们是从行为数据渐进放权——在「自进化」方向上我们更靠前
- **窗口活动流水作为记忆数据源**：全量采集、本地预聚合，避免了对话式记忆「只记说过的、不记做过的」的盲区
