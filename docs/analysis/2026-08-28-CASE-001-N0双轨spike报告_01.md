## 速度实测（RTX 5060 Laptop，bf16）

| 项 | WeMM-2B 本地 GPU | qwen3-vl API |
|---|---|---|
| 模型加载 | 9.5s（VRAM 5.1GB） | — |
| 文本语料 embed | 均 269ms/条（P50 136ms，P95 1512ms 长文） | 均 164ms（P95 185ms） |
| 查询 embed | **42ms（P95 44ms）** | ~150ms（P95 182ms） |
| 图片 embed | 320ms/张 | 未测（链路同视频） |
| 10s 视频 embed | 2.7s/段 | 1.0s/段 |

- 查询 42ms：启动器即时检索完全可行（一期验收线 P95<500ms）；
- opt-in 视频成本：30 分钟视频 = 180 段 × 2.7s ≈ **8 分钟 GPU 后台时间**，可行；
- CPU（fp32，无 GPU 参考值）：文本单条 ~1.4s——启动器查询场景超一期 500ms 验收线；10s 视频段预估 30s+，**无 GPU 机器视频索引基本不可用**（N1 侧 car 产品化时需明示）。

## 踩坑记录（N1 产品化必须处理）

1. **HF 下载**：huggingface_hub 新版默认 xet 协议，其后端不被 hf-mirror 代理（401），必须 `HF_HUB_DISABLE_XET=1`；
2. **torchvision 缺失静默置空**：transformers 5.2.0 的 video processor auto mapping 在无 torchvision 时全部注册为 None，报 `argument of type 'NoneType' is not iterable`——sidecar 依赖清单必须含 torchvision；
3. **必须显式 trust_remote_code**：transformers 5.2.0 主线认识 `qwen3_5` 架构，不带 trust_remote_code 也能加载但得到无 `embedding()` 的裸类（静默拿错类，最阴险的坑）；
4. **batch 需 padding=True**，且已验证 batch 内与单跑余弦=1.0（embedding token 位置提取正确）；
5. **显存**：fp32 需 8GB+ 超 5060 Laptop 显存，bf16 占 5.1GB——8GB 显卡只能 bf16，加载后剩余显存 ~1.8GB，批大小受限；
6. WeMM-2B 架构实为 `qwen3_5`（Qwen3.5 系），依赖 transformers==5.2.0 + qwen-vl-utils[decord]==0.0.14 + torchvision + accelerate。

## 对裁决的更新建议（需 LHF 确认）

| 项 | 原裁决 | spike 后建议 |
|---|---|---|
| WeMM 维度 | 512 截断初值 | **改定 2048 全维**（512 裸查询 81% 不过线；2048+指令 94% 全场最高）。存储 8KB/条，10 万条 800MB 可接受 |
| 查询指令 | 未规定 | **纳入规范**：查询侧固定 instruct 前缀，语料侧不加；API 与 WeMM 同文案 |
| top-1 偏低（69% vs bge 81%） | — | 接受：红线是 top-3 且已反超；N1 融合排序时注意记忆结果给 top-3 窗口而非只取第一 |
| 无 GPU 机器 | 「sidecar 本地为终点」 | 保留风险：CPU 文本查询 ~1.4s 超验收线、视频不可用。N1 产品化时定 CPU 机器策略（降级仅文本 or 引导云端模式） |
