## 发现

### HIGH

**H1. 黑名单首次同步会清空扩展本地清单（迁移期数据丢失）** — `extension/background.js` `syncBlacklist()`
SQLite 单真源切换后，M2 时代写入 `chrome.storage.local` 的黑名单没有迁移路径：首次同步用 SQLite 列表（新表，空）无条件覆盖本地缓存，M2 时代拉黑的站点被一次性抹掉。本次改动前刚拉黑的域名靠 `pending_ops` 重放能幸存，但 M2 存量没有 pending_ops。
修复方向：一次性迁移——加 `nervis_blacklist_migrated` 标记，首次同步时若 host 列表为空且本地非空，改为把本地逐条 `block_domain` 推给 host，置标记后再走正常拉取。

### MEDIUM

**M1. popup.js 黑名单渲染用 innerHTML 拼接域名（自我 XSS 面）** — `extension/popup.js:21`
Rust 侧 `add_blacklist` 只校验「含 `.`」，`x.<img src onerror=...>` 可入库并被 popup 以 innerHTML 渲染。需先控制设置页输入才能触发（自我 XSS），但修复廉价：`textContent` 赋值 + Rust 域名字符集白名单校验（`[a-z0-9.-]`）。

**M2. fact_pipeline `block_on_llm` 的 panic 路径会杀死 MCP 进程** — `src-tauri/src/companion/fact_pipeline.rs`
`catch_unwind` 后 `.expect("fact_pipeline LLM runtime")`：LLM future 一旦 panic（如未来在 current_thread runtime 上下文误用 block_in_place），整个 companion MCP server 进程死亡，Claude Code 侧工具通道断开。应改为返回 Err 回落 bigram 路径——与全链路隐身降级原则一致。

**M3. 低于阈值的召回分数不落标定日志（D12 设计意图缺口）** — `src-tauri/src/companion/tools.rs`
阈值标定需要全量分数分布，目前只有 ≥0.65 的路径把 `vec=score` 写进审计 source；<0.65 走 bigram 时分数丢失，「差点够到阈值」的样本在标定时不可见。bigram 路径写入时带上召回分数（如 `explicit|vec=0.52|below`）即可补齐。

### LOW

- **L1** `memory-host.rs` `read_frame` 无帧长上限（u32 最大 4GB 分配；仅注册扩展可达，健壮性问题）——加 32MB cap
- **L2** `content.js` 黑名单只在注入时读一次——已打开的页面被拉黑后要刷新/跳转才停止采集（可接受，记为已知行为）
- **L3** 已提交的 `extension/native-host/com.nervis.memory.json` 含开发机绝对路径——属生成物，建议 .gitignore 或在文档注明由 `install_native_host.py` 再生成
- **L4** `memory_items.created_at` 格式混用（browser/subtitle 为 ISO8601，其余为 `%F %T`）——仅展示字段，不参与排序
- **L5** B站 `#t=` 锚点可能不生效（B站 时段参数为 `?t=`，YouTube `#t=` 有效）——待 B站 实测确认后按站分流
- **L6** `install_native_host.py` 默认指向 release 二进制——dev 改了 host 协议必须 `cargo build --release -p nervis-memory`，否则浏览器拉起旧协议（本次「黑名单不同步」故障根因）。CLAUDE.md 补一句开发注记
