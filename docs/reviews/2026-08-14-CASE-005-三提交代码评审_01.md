## CRITICAL（2）

### C1. 硬拒绝规则只认「首词」→ 任意前缀组合静默执行递归删除 / 注册表删除 / 账户创建

**位置**: `src-tauri/src/companion/shell.rs:182-218, 240-249`

`hard_deny_reason` 对 `del|rd|rmdir + /s`、`reg delete`、`net user/localgroup`、`cipher /w`、`rm -rf` 全部是 `first == X && has(flag)` 首词规则。CASE-004 D1 明确要求「整串 token 扫描、位置无关、嵌套 cmd /c 照样命中」。危险动词出现在非首词位置时不拦，unattended 下静默执行。

**已实测复现**（本机真实 cmd，全部静默执行递归删除）：
- `echo x & del /s /q a`
- `cmd /c "dir & del /s /q a"`（剥壳递归只把剥壳后串按空白重切，引号结构丢失）
- `start cmd /c "del /s /q a"`（start 不在剥壳逻辑）
- `cmd /k del /s /q a`（剥壳只找 /c 不找 /k）
- `if exist a del /s /q a` / `for /f %i in (...) do del /s /q ...`
- `C:\Windows\System32\cmd.exe /c del ...`（剥 .exe 后是完整路径 ≠ "cmd"）
- `cmd /x /y /z /c del ...`（`pos <= 3` 截断剥壳）

**修复**: 危险动词按 cmd 分隔符（`& | ( )` 及 `cmd /c|/k`、`start`、`call`、`if`、`for`、`do` 之后）切段，对每一段执行首词规则；剥壳对任意位置 `cmd` token（剥 .exe 后 basename 匹配）处理 `/c` 与 `/k`，去掉 `pos <= 3` 魔法数。

### C2. 敏感路径片段匹配漏检「目录无尾反斜杠」「cd 后相对访问」→ 静默读取私钥/凭证

**位置**: `src-tauri/src/companion/shell.rs:670-696, 394-397`

`KEY_DIRS` 片段全是 `\.ssh\`（首尾带反斜杠）形式，两个结构性漏口：

1. `findstr /s /i "PRIVATE KEY" C:\Users\xxx\.ssh`（`.ssh` 在串尾，`\.ssh\` 不命中）→ 递归搜出私钥全文发云端模型；`for /r C:\Users\xxx\.ssh %f in (*) do @type %f` 整串不含任何敏感片段。
2. `cd /d %USERPROFILE% & type .ssh\config` → 展开后 `.ssh\config` 前是空格，文件名 `config` 不在 KEY_FILES → 漏检；cmd 执行时相对路径读到真实文件（`known_hosts`、`*.ppk` 同理）。

CASE-004 D5 原话「漏过代价 = 密钥上云」，这两条正是漏过路径。

**修复**: 目录判定改为路径段匹配——按 `\` `/` 空白切段，敏感目录名（`.ssh` `.aws` `.gnupg` `.kube` `.docker` `.azure`）作为独立段命中即拒；对「敏感目录段命中 + 存在读动作动词」做联合判定，宁宽勿窄。

## 结论与建议

**决策：BLOCK**。必须修复 2 CRITICAL 后再发版；12 个 HIGH 建议合并修复（H1/H2/H3/H4/H5/C1/C2 同源于「首词/精确 token 匹配」→ 统一重构为「切段判定 + 前缀匹配 + 路径段匹配」）。

建议修复顺序：
1. **第一批（安全边界）**：C1 + C2 + H1-H5——shell.rs 判定层重构（切段、前缀匹配、路径段匹配），附带 M3 的 clippy 修复与 L3 注释修正
2. **第二批（环境感知管线）**：H-1（整轮保留缓存）+ H-4（async command 或 spawn_blocking + 失败背压）合并改；H-5 的 get_settings 脱敏
3. **第三批（MCP 加固）**：H-2（响应限量读取）+ H-3（SSRF 防护 + last_error 不含响应体）+ M-5（工具数/schema 上限）+ M2（untrusted 包裹）
4. **第四批（前端体验）**：前端 H1（IME 组合态）、M2、M3、M6
5. 其余 MEDIUM/LOW 按节奏排期

正面结论：执行层引号肢解修复本身正确（集成测试在真实 cmd 验证通过）；三层黑名单骨架与裁决一致；测试覆盖好（208 测试全过）；前端无 XSS/注入面；前端类型检查与 Rust 编译均绿。
