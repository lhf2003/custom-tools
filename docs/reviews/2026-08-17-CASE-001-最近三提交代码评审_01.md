## Findings

### HIGH

#### H1. 重复备忘再生无幂等守卫 → 可复制出重复的下一次备忘
- **位置**: `src-tauri/src/commands/companion.rs:400-413`（配合 `src/modules/memo/MemoView.tsx:358-360`）
- **问题**: `set_memo_status(status="done")` 无条件取整行并 `create_next_recurrence`，不检查备忘先前状态。主视图「已完成」组的勾选可把 done 勾回 pending 再勾回 done（toggle 明确支持），每次 pending→done 都 INSERT 一条相同 due 的新 occurrence → 重复条目可无限增殖。便签上快速双击勾选也可能双发。
- **修复建议**: 仅在取到的旧状态 `m.status != "done"` 时重生（`if m.status != "done" && m.recurrence.is_some()`），或对 (parent_id) 加唯一约束。
- **已修复（2026-08-17）**: `db::set_memo_status` 改为条件 UPDATE（`WHERE status != ?2`）返回实际迁移行数，命令层仅迁移 >0 时重生——done 重复勾选、双击双发均被原子拦截。单测 `set_memo_status_reports_actual_transition`。

#### H2. 下一次 occurrence 不继承 pinned → 桌面便签核心场景断裂
- **位置**: `src-tauri/src/companion/db.rs` `create_next_recurrence` 的 INSERT 语句
- **问题**: INSERT 未包含 `pinned`（落默认 0）。用户把「每天喝水」钉到桌面便签（sticky 只显示 pending+pinned），在便签上勾选完成后，新 occurrence 未钉 → 便签从此不再显示它。钉在桌面的重复备忘完成一次即永久消失，与「重复备忘+桌面便签」两个 P1 特性的组合预期矛盾。
- **裁决（2026-08-17）**: 继承。✅ 已修复：INSERT 补 `pinned` 照抄旧行；取消钉当前一条即整链退出。附单测 `next_recurrence_inherits_pinned_and_rule`。

#### H3. 「全部标为完成」批量路径不重生重复备忘
- **位置**: `src-tauri/src/commands/companion.rs:435-454` `bulk_set_memo_status`
- **问题**: 批量 pending→done 直接 UPDATE，与单条完成行为不一致：用户用「全部标为完成」处理重复备忘后，周期链静默断裂，且无任何提示。
- **裁决（2026-08-17）**: 也重生，与单条完成行为一致。✅ 已修复：bulk 前经 `list_pending_recurring` 捞出待办重复备忘，批量迁移后逐一重生（done→dismissed 不重生）。单测 `list_pending_recurring_filters_done_and_plain`。

### MEDIUM

#### M1. TriggerGrid 的 key 在同插件多 trigger 时不唯一
- **位置**: `src/modules/launcher/LauncherView.tsx:127-135`（suggestResults 的 `path: builtin://${plugin.id}`）与 TriggerGrid `key={item.path}`
- **问题**: 内置插件目前均为单 trigger 不触发；但外部插件 manifest 可声明多个 trigger（`src/plugins/external.tsx:29`）。裸「@」全列出时，同插件多关键词 → React key 重复 + 网格中两张同名无区分卡片（网格形态省略了关键词信息）。
- **修复建议**: key 用 `${plugin.id}:${keyword}`；或网格卡片补关键词副文本。
- **已修复（2026-08-17）**: TriggerGrid key 改 `${item.path}:${index}` 补唯一。path 格式不动——它会经 handleItemClick 记入 app_usage、下次启动按 `replace('builtin://','')` 反解析 toolId，改格式会破坏打开逻辑。

#### M2. 便签窗口位置无屏界钳制
- **位置**: `src-tauri/src/companion/sticky.rs` `saved_position` / `show_window`
- **问题**: 保存的位置直接回放，不做显示器边界校验。拔外接屏后位置落在可视区外 → 便签永久不可见，且关闭再开仍用旧位置，菜单开关没有重置路径。
- **修复建议**: set_position 前用当前显示器工作区钳制（或 show 失败时回退默认位置）。
- **已修复（2026-08-17）**: `clamp_to_screen`——按 current_monitor / 落点所在屏 / 主屏链式取显示器，右/下侧留出窗口自身尺寸后 clamp。

#### M3. 便签乐观移除失败无回滚
- **位置**: `src/modules/memo/sticky/MemoStickyView.tsx` `complete()`
- **问题**: 失败分支只有 `console.error`，条目已从本地状态移除且无事件回流 → 与库静默失同步，直到下一次 memo:changed。
- **修复建议**: catch 中恢复条目（或触发 load()）。
- **已修复（2026-08-17）**: catch 中 `void load()` 重拉对齐（成功路径事件回流再刷一次，重复拉取幂等）。

#### M4. 新逻辑无测试
- **位置**: `db.rs` `next_due_date`（纯日期计算，边界明确：今天即周N→下周、1..=7 钳制）；前端 `recurrenceLabel`、repeat 过滤
- **问题**: 无任何单测。前端暂无测试基建可接受；Rust 侧建议至少为 next_due_date 补 table test。
- **已补（2026-08-17）**: `next_due_date_daily_and_weekly_rules`（daily/本周/跨周/集外丢弃）+ `next_recurrence_inherits_pinned_and_rule`（继承、规则与 due 落库）。
