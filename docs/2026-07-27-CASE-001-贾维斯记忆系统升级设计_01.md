# 贾维斯记忆系统升级设计

**创建日期**: 2026-07-27
**作者**: LHF & Claude
**版本**: v1.0
**状态**: 已批准

## 背景

对照 `docs/alice-methodology/`（Alice 方法论）完成差距分析后，确认贾维斯陪伴系统最薄弱的层是**记忆系统**：

- 聊天内容完全不进记忆（facts 只从活动摘要挖，最优质的用户偏好信号流失）
- memory_facts 注入是 top-50 盲注，无维度分组、无场景选维
- 聊天 agent 无即时记忆工具（用户说「记住X」无处落库）
- 记忆无治理：无审计、无管理 UI、无变更追溯

本文档记录一期升级方案。分析方法与差距详情见 alice-methodology 第 5 章（上下文与记忆）、第 9 章（Skill）、第 14 章（提示词工程）与 blog-04（五层记忆架构）。

## 已裁决的 7 项决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 主攻方向 | 记忆系统升级（优先于 Skill 化、状态层、地基加固） |
| 2 | 提取时机 | Alice 式逐会话提取（debounce）+ 显式「记住X」即时落库 |
| 3 | 提取架构 | 新增「记忆提取」独立场景（缺省跟随 companion 模型，可改绑）；单调用，无守门员 |
| 4 | 分类体系 | 五类：person / project / workflow / voice / expectation；旧标签迁移（general→workflow、preference→voice），analyst 与聊天提取共用 |
| 5 | 注入策略 | 聊天按五类分组全量注入；日报/分析额外注入 voice+expectation 两维；相关度召回推迟到 facts > 150 |
| 6 | 情感记忆 | 二期与状态层（时间带/忙碌度/内心独白）合并做 |
| 7 | 记忆中心 | 全量功能（五类列表+搜索+编辑/删除+变更审计），入口为陪伴设置页二级菜单 |

## 工程设计

### 1. 数据层（companion/db.rs)

**新表 memory_fact_events（变更审计）**:

```sql
CREATE TABLE IF NOT EXISTS memory_fact_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    fact_id INTEGER,            -- 删除后保留 NULL 亦可，事件内自存文本快照
    action TEXT NOT NULL CHECK (action IN ('add','confirm','update','delete')),
    old_text TEXT,
    new_text TEXT,
    category TEXT,
    source TEXT NOT NULL,       -- daily_analysis | recall | explicit | user
    created_at INTEGER NOT NULL
)
```

**幂等迁移**（init_tables 内，每次启动跑、首次后空转）:

- `UPDATE memory_facts SET category='workflow' WHERE category='general'`
- `UPDATE memory_facts SET category='voice' WHERE category='preference'`

**CRUD 变更**:

- `upsert_memory_fact` 内部改为「先查后写」:新增→审计 add；已存在→confirmations+1 → 审计 confirm。签名不变，现有调用方（daily_analysis）自动获得审计
- 新增 `update_memory_fact(id, fact, category, source)` → 审计 update（记录 old→new）
- 新增 `delete_memory_fact_audited(id, source)` → 审计 delete（事件存文本快照，历史不随删除丢失）
- 新增 `list_memory_facts_by_categories(cats, limit)`（日报选维注入用）
- 新增 `list_memory_fact_events(fact_id?, limit)`（记忆中心审计视图用）

### 2. 逐会话提取管道（新模块 companion/recall.rs)

**触发（debounce)**:

- 前端在每条消息落库后调用 `jarvis_recall_poke`（用户发送与回复完成两个时点）
- poke 递增全局 generation 计数；常驻防抖任务每 10 分钟醒来比对，计数有变化且距上次提取已过静默期则执行提取
- 夜间兜底：21:00 调度块（run_scheduler 现有线程）在每日分析后无条件调用一次 `run_recall`（水位已最新则空转）

**水位**:settings 表 `companion_recall_watermark` 记录已提取到的 chat_messages.id；失败不推进，下次重试。

**提取范围**:`chat_messages JOIN chat_sessions`,role='user'、mode='chat'、id > 水位，升序限 30 条（超出部分留下次）。translate 等工具模式不提取。

**Prompt 结构**（镜像 analyst 流）:persona + evolution + `agents/recall.md` 手册 + 已有记忆（按五类分组、带 id，上限 100 条）+ 本次用户消息（带 msg id，按时间序）。

**输出契约**（只输出 JSON):

```json
{"ops": [
  {"action": "add", "fact": "一句话事实", "category": "voice"},
  {"action": "update", "target_id": 12, "fact": "覆盖后的新表述", "category": "person"}
]}
```

- add → upsert（审计 add/confirm，source=recall)
- update → 覆盖 target 的 fact/category,confirmations 保留、last_confirmed 刷新（审计 update);target_id 不在现有集合则降级为 add
- ops 为空 = 本轮无可记（内置「没有值得记的就返回空」纪律，不做独立守门员）

**LLM 路由**:`call_llm_with_scene(..., Scene::MemoryExtraction)` — Claude Code 开→oneshot；关→场景模型。场景模型查询缺配置时回退 Companion 场景配置。

### 3. 手册 agents/recall.md

聊天记忆提取工作手册（非分身人格，贾维斯日常工作之一），要点：

- 只从用户消息提取；工具结果、贾维斯自己的回复一律不作依据（防自我强化）
- 五类定义与示例；每类最多 2 条，没有就空
- 不该存：可从数据直接查到的、临时任务状态、隐私细节（密码/密钥/聊天原文大段引用）
- update 的使用时机（用户纠正/覆盖旧事实）vs add（全新事实）
- 输出 JSON 契约与「空结果合法」纪律

persona.rs 的 `load_role` 增加 "recall" 分支，同款播种机制。

### 4. MCP 工具 ×2(companion/mcp.rs)

- `remember_fact(fact, category)`：显式记忆即时落库，source=explicit，审计 add。category 提示五类
- `forget_fact(keyword)`:LIKE 匹配删除，单次最多 5 条，逐条审计 delete；无匹配时明确告知

场景模型回退路径下 agent 无工具，显式记忆请求由 debounce/夜间兜底提取代为捕获（非即时但不丢）。

### 5. 场景配置（llm_provider)

- Scene 枚举新增 `MemoryExtraction`(snake_case: memory_extraction，中文别名「记忆提取」)
- 模型设置页场景列表加一行；未配置时后端回退用 Companion 场景配置
- `call_scene_model_llm` 加 scene 参数；非 Companion 场景查不到配置时降级 Companion

### 6. 注入调整

- 聊天系统提示（chat.rs compose_chat_system):「你记住的他」按五类分组排版（他是谁/他的项目/他怎么做的事/他的表达偏好/他对你的期望），未知类别归入「其他」；仍限 50 条
- 日报双路径（agent.rs build_report_prompt、analyzer.rs run_scene_report)：注入 voice+expectation 两维事实，让日报语气贴合用户表达偏好与对贾维斯的期望

### 7. 前端

- **ChatView.tsx**:jarvis:done / llm:done（及用户发送）后 `invoke('jarvis_recall_poke')`
- **陪伴设置页 → 记忆中心二级视图**:
  - 五类分组列表（未知类归「其他」)，关键词搜索（前端过滤）
  - 每条支持编辑（文本/分类）、删除；均写审计（source=user)
  - 每条可展开变更历史（来自 memory_fact_events)
  - 入口为陪伴设置页内入口卡片，二级视图带返回
- **模型设置页**：场景列表新增「记忆提取」行

### 8. 新增 Tauri 命令

- `jarvis_recall_poke`（防抖触发，前端每条消息后调用）
- `companion_memory_facts`（全量列表）
- `companion_update_memory_fact(id, fact, category)`
- `companion_delete_memory_fact(id)`
- `companion_memory_fact_events(fact_id?)`

## 边界声明

- expectation 维度只进记忆层与注入，**不改 persona.md**——人格恒定区只走人工修改（Alice 核心身份保护原则的对应物）
- 相关度召回（关键词/向量）不做，facts > 150 再议
- 情感记忆（贾维斯日记）不做，二期与状态层合并
- 守门员两阶段提取不做，单调用内置空结果纪律
- 子 Agent 独立人设不做（维持「贾维斯+工作手册」体系）
